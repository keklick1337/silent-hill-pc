# Rendering

Reference for the engine's graphics: the RHI and its backends, the `sh::gpu` primitive renderer, the engine frame and draw order, drawer commands, the glb scene, settings and presets, debugging. There is no emulation of the console's GPU or GTE. What remains of the original are the rules the game draws by: a 1024×512 VRAM as texture store and frame feedback, blend modes, ramp fog, dithering, depth buckets. All of it is implemented by engine classes.

## 1. Overview

```text
game drawers (src/engine/*/game, src/render/world, src/ui/screens, Lua sh.render)
   │  sh::draw2d / sh::draw3d commands, scene items, by order key {layer, slot}
   ▼
engine frame  sh::frame::Frame (render/frame)            ── draw order
   ▼  sh::gpu::display::draw_layer → draw_frame_entry (render/gpu/frame_draw)
SplitBuilder (rhi::PrimVertex stream + splits)           ── render/gpu/split_builder
   ▼  flush
sh::gpu::Renderer: SplitRenderer, ShadowPass, FeedbackPass, Targets, PostPass  ── render/gpu
   │  scene splits → sh::scene::SceneRenderer (render/scene)
   ▼
RHI (render/rhi): GL 3.3 core | Vulkan | SDL3 GPU        ── present to the window
```

## 2. RHI and backends

### 2.1 Interface

`src/render/rhi/rhi.h`: `Device` (textures, buffers, samplers, shaders, pipelines; generational handles; `begin`/`submit`/`readback`), `CommandList` (uploads and copies outside a pass, `beginRenderPass`, `acquireSwapchainTexture`, `blitTexture`), `RenderPass` (pipeline, viewport, scissor, blend constants, stencil reference, vertices and indices, samplers, std140 push uniforms by slot, `draw`/`drawIndexed`). Errors are `sh::Result`. No GL types leak out.

Common backend conventions:

- clip space as in GL: NDC +Y up, Z in [−1, 1]; a backend with Z in [0, 1] converts it in the shader (`SH_RHI_CLIP_Z01`: `z = (z + w) / 2`);
- viewport, scissor, upload and readback rectangles are from the top-left corner, +Y down; readback returns rows top to bottom;
- drawing only inside a pass, uploads on the command list outside a pass;
- `gl_FragCoord` is top-origin on both Vulkan backends, so the dither phase and the deband noise are computed from the GL coordinate `H − y` (target height in a uniform); otherwise the pattern would shift by rows.

### 2.2 Backends

| `renderer` | Backend | Notes |
| --- | --- | --- |
| `gl` (default) | `rhi_gl.{h,cpp}`: GL 3.3 core | Own GL function table (loader `SDL_GL_GetProcAddress`), cache of applied state, a UBO ring for push uniforms with unsynchronised mapping, an FBO per target pair. After overflow the ring rewrites the last blocks of all slots (otherwise other slots' blocks would point at garbage) |
| `vulkan` | `rhi_vulkan.{h,cpp}`: the engine's own Vulkan device, SPIR-V | See 2.2a |
| `sdlgpu` | `rhi_sdlgpu.{h,cpp}`: SDL3 GPU, SPIR-V | Uploads via transfer buffer + copy pass (vertex buffer with `cycle`), readback via fence, depth D24S8 with fallback to D32S8. The game window is presented by the SDL3 GPU device; present mode FIFO with vsync, otherwise immediate or mailbox |

- Any other `renderer` value is replaced by `gl` at start with a log line (`game_main.cpp`); `-renderer <name>` on the command line overrides the config.
- Options > Graphics > Renderer (`setting.renderer`, `src/ui/menu/options_binds.cpp`) cycles `gl`, `vulkan` and `sdlgpu` and saves the key; the backend is chosen before the window opens, so the change applies at the next start and the Restart Now row below it (`options.restart`, through `sh::mods::request_restart`) appears while the choice differs from the running backend. Until the player changes it the row shows the backend that runs, so after a failed `vulkan` start it reads the backend that took over, and when that is OpenGL its help line says Vulkan could not start. With `-renderer` on the command line the row is locked and its help line says so.
- `vulkan` that cannot start (no loader, no device with dynamic rendering and synchronization2, no SPIR-V in a build without `glslc`) falls back to `sdlgpu`, and `sdlgpu` to GL, each with a warning. Under `SDL_VIDEODRIVER=offscreen` the SDL3 GPU device has no surface on drivers without `VK_EXT_headless_surface` (NVIDIA) and falls back to GL; the native backend runs surfaceless there (2.2a).
- The SDL3 GPU backend stays as the fallback and the comparison path: it hides its Vulkan objects (no ray tracing, no compute, no timestamps), so the modern graphics features (sections 7.10–7.14, 10–13) build on the native backend only.

### 2.2a Native Vulkan backend (`rhi_vulkan`)

- **Dependencies** (vendored, built from source, [COPYRIGHT.md](../COPYRIGHT.md)): Vulkan-Headers (C headers), volk (opens `libvulkan.so.1` / `vulkan-1.dll` at run time, so the MinGW build links no import library), Vulkan Memory Allocator (`vk_mem_alloc.cpp` holds its implementation). Standard Vulkan only: core 1.3, or 1.1 with `VK_KHR_dynamic_rendering` and `VK_KHR_synchronization2`; no vendor extension.
- **Same conventions as SDL3 GPU**, so the shaders and the callers serve both (`rhi::spirvBackend`): the same SPIR-V, set 0 vertex samplers, 1 vertex uniforms (dynamic uniform buffers), 2 fragment samplers, 3 fragment uniforms, binding = slot; the viewport is flipped (negative height) so NDC +Y is up; depth in [0, 1]; textures store the top row first. A slot the shader declares but nothing binds reads a 1×1 dummy.
- **Pipelines** are created per attachment format (dynamic rendering): the declared formats at creation, another variant when a pass's attachments differ (the BGRA8 swapchain). Dynamic state: viewport, scissor, blend constants, stencil reference.
- **Memory and synchronisation**: two frames in flight, each with its command buffer, fence, descriptor pools and host-visible rings (upload staging, uniform data); released objects wait for the last submission that may use them. Sampled textures rest in the shader-read layout, targets in the attachment layout; render passes and copies move them with full barriers (coarse on purpose, the frame is small). Copies between passes form one "transfer" section. Writes into a buffer are ordered by those barriers instead of SDL's cycling.
- **Swapchain**: its own, on the window's SDL surface; `B8G8R8A8_UNORM` or `R8G8B8A8_UNORM` in sRGB non-linear (SDR as on SDL3 GPU); FIFO with vsync, otherwise immediate, else mailbox; made again on resize, `OUT_OF_DATE` / `SUBOPTIMAL` and a present mode change; nothing while minimised. A failed submit or present counts towards the device-lost rule of `DeviceHost` (3.1); `VK_ERROR_DEVICE_LOST` stops all further frames.
- **Surfaceless**: under `SDL_VIDEODRIVER=offscreen` there is no surface; `acquireSwapchainTexture` hands out an image of the backend's own at the window's size, everything else (passes, overlay, readback, the in-engine screenshot) runs as with a window. This is how Vulkan images are captured on NVIDIA here.
- **Capability record** (`rhi::VulkanCaps`, `rhi::vulkanCaps(device)`): API version, vendor / device / driver, device type, subgroup size, device-local memory and the `VK_EXT_memory_budget` budget, the presence of `VK_KHR_acceleration_structure`, `VK_KHR_ray_query`, `VK_KHR_ray_tracing_pipeline`, `VK_EXT_mesh_shader`, `VK_EXT_swapchain_colorspace`, `VK_EXT_hdr_metadata`, the tessellation feature and timestamps. Logged at start (`[GPU]` lines).
- **Profiling**: with the profiler on, a timestamp pair around every render pass (`RenderPassDesc::name`: scene, shadow, post, overlay, fmv, ...) and every transfer section; the profiler overlay lists them per frame and the log repeats them every 10 s (`[GPU] pass times per frame`). "VRAM game" is the process's device-local use from `VK_EXT_memory_budget` (label "driver").
- **Validation**: `vulkan_validation = 1` loads `VK_LAYER_KHRONOS_validation` when it is installed; its messages go to the log as `vulkan validation` warnings.
- **Float targets**: `RGBA16F` (`Caps::floatTargets`, checked against the format features at start): sampled with linear filtering, colour target with blending, blit source and destination, readback (clamped and rounded to 8 bits, as a blit to UNORM). GL and SDL3 GPU refuse the format.
- **HDR10 swapchain** (`rhi::vulkanSetHdrOutput`, `rhi::vulkanHdrStatus`): with `VK_EXT_swapchain_colorspace` and a surface format `A2B10G10R10` / `A2R10G10B10` in `VK_COLOR_SPACE_HDR10_ST2084_EXT` the swapchain is made in it, `VK_EXT_hdr_metadata` (enabled when present) gets BT.2020 primaries, D65, the peak and paper white; otherwise SDR, with the reason as `VulkanHdrBlock`. The backend only picks the colour space; the engine writes the PQ values (7.10).
- **Frame pacing** (`rhi::vulkanSetFramePacing`, 7.13): `present_mode` 1–4 picks FIFO, mailbox, immediate or FIFO relaxed over the vsync choice (a mode the surface lacks falls back to FIFO; 0 keeps the choice above); `frames_in_flight = 1` makes the start of a frame also wait for the fence of the frame before; `present_wait` waits, with `VK_KHR_present_id` and `VK_KHR_present_wait` (enabled with their features when the device has both and there is a surface), until the frame before the last one is on screen (100 ms at most), so at most one frame is queued for the display. Present ids rise across swapchains; a wait only names an id of the current one. Surfaceless runs have no swapchain: only `frames_in_flight` acts there.
- **Model upscaling stages** (7.11): the `tessellationShader` feature and `VK_EXT_mesh_shader` (task and mesh shaders, with Vulkan 1.2 for SPIR-V 1.4) are enabled when the device has them (`Caps::tessellation`, `Caps::meshShaders`, the reason in `Caps::meshShadersMissing`). `PipelineDesc::tessControlShader` / `tessEvalShader` make a patch pipeline (GL's lower-left domain origin, so patches keep their winding); `taskShader` / `meshShader` replace the vertex stage (`RenderPass::drawMeshTasks`). The stages before rasterisation share sets 0 and 1 with the vertex stage; read-only storage buffers (`BufferDesc::shaderRead`, `ShaderDesc::storageBuffers`, `RenderPass::bindStorageBuffer`) are the backend's own set 4. `RenderPass::beginTimedSection` / `endTimedSection` time draws inside a pass (profiler list). GL and SDL3 GPU refuse these stages and leave the new calls empty.
- **Not supported**: multisampled targets (`Caps::maxSamples` 1, as on SDL3 GPU); storage images and compute through the RHI (ray tracing and the atmosphere use them natively, 2.2b, 7.12).
- **Native access** (`rhi_vulkan_native.h`): the engine's own passes that the RHI does not express (ray tracing, 2.2b) get the device, the allocator, the recording frame's command buffer outside any pass, the frame slot, the native image and buffer of an RHI handle, deferred release (`vulkanRetire`), profiler spans, and register their own images as sampled RHI textures (`vulkanAdoptImage`). Only code built against the vendored Vulkan headers includes it.
- **Own passes**: `rhi_vulkan_native.h` hands code linked into `sh_rhi` the device, the allocator, the frame's command buffer outside any pass, the images of backend textures with tracked layout changes, profiler spans and deferred release. Compute, storage images and float formats are used there directly, in files of their own (`vk_atmosphere.cpp`, 7.10), not through the RHI interface.
- A CPU device (`VK_PHYSICAL_DEVICE_TYPE_CPU`, lavapipe) is never chosen (`VulkanDeviceDesc::allowCpu`, off): with no other device the backend fails and the chain falls back to GL, as does `sdlgpu` on a device whose name is a CPU renderer's (2.2c): the GL path is the one tuned and measured on llvmpipe.
- There are no ANGLE or GLES backends: the RHI has no ES dialect. Android would need an ES dialect in `rhi_gl.cpp` (`#version 300 es`, precision, an extension for `noperspective`).

### 2.2b Ray tracing (`rhi_vulkan_rt`)

Ray-traced shadows, reflections and bounce light (section 11) on the native backend only; standard extensions only (`VK_KHR_acceleration_structure`, `VK_KHR_ray_query`, `VK_KHR_deferred_host_operations`, Vulkan 1.2 buffer device addresses, non-uniform sampler indexing, scalar block layout), no ray tracing pipeline and no vendor library.

- **Device**: when every feature is there the device is created with them (`vulkanRayTracingChain`, `VulkanCaps::rayTracingEnabled`); vertex and index buffers then also carry device addresses and the acceleration-structure input usage, so the structures are built from the scene renderer's own buffers, without a copy. Without them nothing changes.
- **Setting**: `ray_tracing` (config.cfg, Options > Graphics > Ray Tracing), off by default and live. Another renderer, or a GPU without the extensions, locks the row and its help line says why (`rhi::rayTracingSupport`).
- **Scene** (`SceneRenderer::ray_scene`): each cell and world object mesh is a kept mesh (key: the `CellMesh`), one geometry per material range (scene `Blend`, textured, water, posed, no-shadow flags), placed by a 3x4 model-to-view transform composed in double like the draws' model-view; the frame's posed meshes (characters, already in view space) are one mesh of the frame. Isolated item previews are left out. Rays work in the frame's view space.
- **Acceleration structures** (`RayTracer::build`, before the first scene draw of a frame into the scene target): a bottom level per kept mesh, built once with `PREFER_FAST_TRACE | ALLOW_COMPACTION` and at most 48 new ones (64 MB of scratch) per frame, so entering a map spreads its builds; compacted when its frame slot comes round again (the compacted-size query is read then, the copy recorded and the original released after the frame); dropped 900 frames after its last use. The posed meshes' structure is rebuilt every frame (`PREFER_FAST_BUILD`). The top level is built every frame per frame slot from a host-visible instance buffer; scratch is one buffer per slot, grown as needed. Untextured opaque ranges are `OPAQUE`; textured ones are tested by the shaders (alpha holes).
- **Profiling**: the spans `rt build`, `rt trace` and `rt denoise`; with the setting on, the log has an `[RT]` line every 600 frames (instances, triangles, kept and compacted structures and their size, top level, scratch, builds of the frame, instances still waiting).
- **Tracing** (`RayTracer::trace`, `shaders/rt_trace.comp`, compute with ray queries, after the build): one invocation per pixel of the scene draw's viewport. The primary ray goes through the pixel centre (the inverse of `scene.vert`'s projection: `SplitRenderer::trace_frame` passes the pixel-to-ray mapping) and stops at what the raster pass shows there: opaque texels, and the solid texels of semi-transparent materials; alpha-0 texels are holes. Each hit reads its range's record (vertex and index addresses, flags, texture slot of a sampler array; the record of a hit is its instance's custom index plus the geometry index) and writes a small G-buffer (normal, view z).
- **Flashlight shadows** (`rt_shadows`): where the beam can reach (inside its cone with the spill, within its range), `shadowRays` rays (2) run from the surface, offset along its normal, to random points of the lens disc (radius 9 view units, scene.frag's `kLightRadius`), so the penumbra grows with the distance to the caster like the PCSS one. They stop the shadow map's near plane short of the lens (the hand that holds it). Holes pass light; translucent texels multiply it by what scene.frag's transmittance layer lets through for their blend; posed meshes that cast no shadow are skipped. The scene fragment shader takes the result instead of the shadow map where the result's view z matches its own (`u_rt`, sampler slot 4); other fragments (blended surfaces in front, edges, the PS1 prims) keep the PCSS.
- **Materials** (section 10; `render/scene/materials.{h,cpp}`, the files by `render/world/surface_material_files.cpp`): one file per material, `gamedata/materials/<Name>.json`, with roughness, metalness, `reflective` (every face) and `wet` (faces turned up), matched by texture page stem (`match`: `DR0101F`, a trailing `*` for a prefix) or pictureless material name, or by rectangles of a page (`regions`: `{"page": "THR7501F", "rect": [x0, y0, x1, y1]}` in pixels of the imported picture; texture pages are atlases, so a window or a shutter is a region of a wall's page). The most specific match wins: a region, then an exact page, then the longer prefix, a hand-written entry before an inferred one. Under them lie the import's proposals (`convert/surface_materials.json`, `sh::convert::materials::write_surface_inference`: per page, from the picture's statistics, floor tiles get a faint wet sheen; pages that are mostly empty filler are skipped); a file of the page's name patches an inferred entry key by key, a mod's file of the same name patches the base one (data_merge.h), any other name is new. Without an entry a surface is neutral, except the water surface (`water.json` "surface"), which mirrors by default. Shipped: the sewers' water and wet floors, the hospital's tiles, the town's window glass and shop shutters (regions of the one-cell house page `THR7501F` and of the common pages `THR0003F` (eight panes) and `THR0004F` (two shutters), which almost every street cell uses; checked in game: both resolve their regions, also under a palette variant such as `THR0003F.thr-2`), the police car's and the ambulance's bodies (painted steel by page). Each geometry record carries its page material and its regions (a per-frame table, binding 8); the trace takes the region holding the hit's UV.
- **Map lights** (`rt_lights`, section 10; `engine/effects/map_lights.{h,cpp}`, `engine/effects/game/map_lights_host.cpp`): `gamedata/maps/<map>/lights.json` names point and spot lights (metres, colour, intensity, range, emitter radius, shadows, bounce, event flag conditions), lights that follow a bone of Harry while an effect is drawn (the match of the opening alley: `"bone": "RightHand"`, `"while_effect": "HandFlame"`, flickering with the flame's own brightness; a gun's muzzle flash gives one the same way, 7.15), a sun and a sky for daytime maps (one fixed direction per location, flag conditions), and the lamp glows: every halo the original draws for a cell's lamp (`glows`) becomes a point light by `gamedata/effects/lamp_lights.json` while no sun shines, which a map may change or switch off. A sun may name `ceilings`: horizontal rectangles (metres, `rect` [x0, z0, x1, z1] and `height`, PS1 axes) for roofs the cells do not draw, whose rooms end at the walls' tops (the school): they block the sun's and the sky's rays (`UnderCeiling` in `rt_trace.comp`, view space, at most 8) and are casters of the raster sun shadow map (7.14), so the sun reaches indoors only through real openings. The frame hook `map_lights` (main_frame.json, after `water`) resolves them into `scene::Frame::lights` / `sun` in world units; the split renderer takes the 32 nearest that can reach the fog's visible range into view space. In the trace each pixel evaluates all lights unshadowed, the strongest takes a shadow ray (to a random point of its radius, stopping short of a held light so the hand does not hide it), one more picked by its share stands for the rest, the sun takes one ray over its disc (64 m; alpha holes of fences and leaves pass light, translucent texels tint it); the fog of the way dims each light, the sun fades with the fog between the eye and the point. Their diffuse light joins the bounce result (times the albedo in the scene shader), their GGX specular lobe and the beam's (PBR-lite: GGX distribution, Smith-Schlick visibility, Schlick Fresnel) join the reflection result on materials that reflect, weighed by their mirror strength, so neutral surfaces stay matte. Reflections and the bounce see the surfaces the lights light; a bounce ray that finds nothing above sees the sky. The volumetric fog (7.10) scatters the 8 nearest map lights (unshadowed). It is only ever added: the original's tint stays the floor.
- **Reflections** (`rt_reflections`): on opaque surfaces and the water whose material reflects (wet ones only where they face up) and is no rougher than 0.6; additive, subtractive and the PS1 averaging surfaces never reflect. One ray per pixel along the mirror direction spread by the roughness; it never goes past the fog's opaque distance (the ramp at full strength, from the frame's fog) minus the surface's own distance, and what it finds is fogged along its own stretch (the shading already fogs the surface) with the fog colour filling the rest; a miss is the fog colour (black indoors). The surface it finds sends back its texture times the map light (the posed meshes their lit colour), darkened under the beam as scene.frag does, plus the beam itself where a shadow ray reaches the lens. Weight: the material's strength times a quarter plus three quarters of the Fresnel term (metals by their colour), because the game's steep camera leaves a plain Fresnel puddle black. The scene shader adds it where the view z matches (sampler slot 5); on the water it replaces the mirrored picture of the posed meshes, but only when mirror rays were traced (`u_rt.y` 2): with `rt_lights` alone the result holds the lights' highlights and the mirrored picture stays.
- **Bounce light** (`rt_gi`): one cosine-weighted ray per pixel from the visible surface, at most 16 m and never past the fog's opaque distance; where it finds a surface the beam lights (a shadow ray from there reaches the lens), that surface's texture times the beam is the light it sends back, dimmed by the fog of the stretch. The scene shader adds it times its own albedo where the view z matches (sampler slot 6). It is only ever added and only the flashlight and the map lights (`rt_lights`) bounce, so a point no lit surface sees is exactly as dark as without it (the original darkness is the floor) and walls block the bounce.
- **Denoiser** (`shaders/rt_denoise.comp`, own): a temporal pass reprojects the last frame's history through the camera motion (`prevFromCur`, the view of each frame) and keeps it where the G-buffer says it is the same surface (view z within 3 %, normals within about 37 degrees), with at least 20 % of the new frame (the beam moves with the player) and at most 24 frames of history; then three edge-stopped a-trous passes (steps 1, 2, 4; 5x5 B3 kernel weighed by depth and normal) write the results. Images are RGBA16F at the target's size; the results are registered as RHI textures (`vulkanAdoptImage`) whose alpha holds the view z they were traced for.

### 2.2c Rendering on the CPU (`software_gl`)

A computer without a usable GPU driver runs the game through the GL backend on Mesa llvmpipe (`src/render/gpu/software_gl.{h,cpp}`, the key `software_gl` in `assets/config.cfg`: `auto` by default, `force`, `off`).

- **Detection**: `DeviceHost::probe_gl_caps` marks the device `HostCaps::software` when `GL_RENDERER` names a CPU renderer (`is_software_adapter`: llvmpipe, softpipe, lavapipe, SwiftShader, Microsoft Basic Render, GDI Generic, swrast). The Vulkan backends never take a CPU device (2.2a) and fall back to GL.
- **Lightest graphics**: with `software_gl = auto` and a CPU renderer, `lighten_for_cpu_renderer` (`game_main.cpp`) applies the `original` preset to this run (no MSAA, no post-processing, point sampling, Classic flashlight and lighting, render scale 1) right after the window opens, before the first frame, except `native_resolution`, which stays as configured (the scene target is sized when the window opens; the key applies only at start), unless the player chose the graphics: `config.cfg` names `graphics_preset` (the shipped file leaves it commented out) or a preset key differs from the default preset (`PcConfig_GraphicsChosen`, `RenderPreset_Matches`). Nothing is written to `config.cfg`. The replay and smoke tools pin `software_gl = off`: their private Xvfb is llvmpipe too, and their pictures keep the config's graphics.
- **Linux**: llvmpipe is the system's Mesa; it takes over by itself when no GPU driver is installed. `force` sets `LIBGL_ALWAYS_SOFTWARE=1` before the first GL window (Mesa only; a vendor GL ignores it).
- **Windows**: the package carries `software_gl/opengl32.dll` and `software_gl/libgallium_wgl.dll` (mesa-dist-win, mingw/UCRT build, fetched and hash-checked by `tools/win-deps/software_gl.sh`). They are in a folder of their own: an `opengl32.dll` beside the exe would replace the system's for every start. `DeviceHost::init_gl` first tries the system's driver; only when no GL 3.3 core context can be made (no driver, or the GDI generic GL 1.1 of the Microsoft Basic Render Driver) does it destroy the window (which unloads the GL library), call `use_bundled_software_gl` and try once more. That function loads `opengl32.dll` by full path with `LOAD_WITH_ALTERED_SEARCH_PATH` (its import `libgallium_wgl.dll` is found beside it), points `SDL_HINT_OPENGL_LIBRARY` at the same path (SDL then uses the library's own `wglChoosePixelFormat` / `wglSwapBuffers`) and sets `GALLIUM_DRIVER=llvmpipe` unless the user set it (the d3d12 and zink drivers of the same DLL are not shipped with what they need), in the process environment and in the UCRT's copy. `force` takes the bundled library without trying the system's; `off` never loads it. No launcher and no restart are needed: the exe does not import `opengl32.dll` (SDL loads GL at run time).
- **Speed**: on four cores of a desktop CPU llvmpipe draws the town and the school at 60 fps and more with the CPU defaults (about half of that with `enhanced`). `original` with `native_resolution` is not faster: at that size the frame's fixed costs dominate, which is why the CPU defaults keep the window's resolution. Under Wine, `WINEDLLOVERRIDES=opengl32=n,b` is needed for the bundled llvmpipe (Wine otherwise answers any `opengl32.dll` with its builtin one).

### 2.3 Shaders

Built-in shaders are written once in GLSL 450 (`src/render/rhi/shaders/`, `src/render/scene/shaders/`, `src/render/gpu/shaders/`, `src/render/overlay/shaders/`, `src/media/fmv/`). At build time `cmake/rhi_embed_shader.cmake` embeds the text (the GL path changes `#version` to `330 core`; differences are covered by `SH_RHI_*` macros) and SPIR-V built by the system `glslc` or `glslangValidator`. Without a compiler the SPIR-V is embedded empty and `vulkan` is unavailable. The CMake option `SH_RHI_SDL3=ON` makes SPIR-V mandatory.

### 2.4 Primitive batch (`prim_batch`)

`src/render/rhi/prim_batch.{h,cpp}` and `shaders/prim_batch.{vert,frag}` draw the frame's vertex stream:

- `PrimVertex` — 68 bytes, `pack(1)`: screen position, page and palette words, flat depth, texel, brightness mode, dither flag, colour, half-texel offset, fog and depth tag, precise position (w = 0 means affine), normal and position in view space, world geometry flag, texel box for the filter;
- pipeline key: original blend mode × depth mode × mask, with a pipeline cache;
- `BM_ADD_QUATER_SOURCE` (B + F/4) uses the blend constant 0.25 (`kQuarterBlendAlpha`) for all blending modes;
- fragment stage: CLUT 4/8/16 from VRAM (format in the vertex), RGBA replacements and frame feedback reads, nearest / bilinear with coverage weight (`BilinearTextureSample`) / anisotropic (`AnisoTextureSample`) sampling clamped to the polygon's UV box, "sharp" sampling for 2D and the font (`SharpTextureSample`, `SharpOverrideSample`), Classic and Modern flashlight with PCF shadows, original fog and soft fog, fog to black for additive and subtractive primitives, 4×4 dithering with 5-bit quantisation, deband, STP folded into alpha for the additive mode.

Known GL vs Vulkan differences: ±1 in interpolation and blending, and the neighbouring 5-bit dither step at a step boundary. There is no backend comparison rig in the repository.

### 3.2 Frame driver

`render/gpu/frame_driver.{h,cpp}`:

- `start()` creates the `Renderer` (window, GL or SDL3 GPU, MSAA) and connects the hi-res replacement lookup;
- `frame_begin()`: `follow_window()` compares the window buffer size (`SDL_GetWindowSizeInPixels`) with the one the targets were made for and calls `window_changed()` on a mismatch. Resize events are not the only path because the movie loop (`src/media/fmv/movie_player.cpp`) drains the event queue; the movie frame (`sh::fmv::present_frame`) calls `follow_window()` too. Targets and the output rectangle are in window buffer pixels; the pointer (in window units) is converted in `window_to_picture`. Then the graphics state is copied into component settings (`sync_state`), the draw area is cleared every frame (a transition frame may draw before the environment is set), and on pause the frozen frame is repeated (`feedback_control().present_last_frame`: the UI lies over the frozen world, as on the console where the frame buffer was not cleared);
- `frame_end()`: the game's feedback flags, `end_scene` (frame into VRAM for the next frame to read, frozen frame capture), `ShScene_FrameEnd`, the 2D overlay (into the scene target; with `native_resolution`, into the window after output), `present` (post, output, swap), `Frame::end_frame`.
- A movie (`src/media/fmv/fmv_renderer`, `sh::fmv::FmvRenderer`) is drawn through the RHI and shown by `Renderer::present_picture()`, without VRAM packing and without a frozen frame capture.

The frame host and the frame buffer source are set by `src/engine/app/game_display_host.cpp`; frame pulses come from `sh::loop::VBlankClock`.

### 3.5 Replacement pictures

`render/textures/replacement_store.{h,cpp}` (`sh::textures::ReplacementStore`) holds full-colour pictures drawn instead of VRAM pictures. 2D screens, fonts and 3D effects select a texture by page and palette; a replacement is an RGBA texture of any size bound to the cells the original occupies and stretched over its place. The world, characters and items are drawn by the scene from the imported glb and PNG (section 6); a mod replaces their pictures with a file at the same path under `convert/`, which this section does not cover.

| Kind | Key | Who puts it |
| --- | --- | --- |
| picture (`put`, `put_rows`) | the original's rectangle in VRAM (16-bit cells), palette cell, colour depth (`PictureKey`) | the picture step after reading a TIM (`GameImageHost` in `engine/app/loader/game_files.cpp`): a mod picture `convert/textures/<FOLDER>/<NAME>.png` / `.dds` whole — one texture under all palette rows of the TIM, `<NAME>.pNN.png` — per row; the game's font pages (`i18n/game_font.cpp`); the input hint atlas (`input/glyphs`) |
| sheet (`put_sheet`) | a number in the palette word with a row from 512 (no such row in VRAM): `sheet_palette(n)` | what the engine draws itself and does not keep in VRAM: the bullet hole sheet (`kBulletHoleSheet`, 5.2a) |

- **Lookup** (`find(page, palette)`, through `PageHooks::lookup_override`): a picture matches when its colour depth is the page's depth, its rectangle intersects the page window (64, 128 or 256 cells right of the page start by depth and 256 rows down) and, if it has a palette, the palette cell matches. Of the matches the one put first wins. The answer is the texture, the original's size in texels (draw coordinates are in them), the page start offset inside the original (a picture wider than one page) and the replacement size. A direct-colour page over the left 320 columns is a frame read and has no replacements; a sheet word on a direct-colour page is not read.
- **VRAM writes** (`cells_written`): when the game writes cells, pictures whose rectangle or palette row they touch are removed, since drawing with that key would now show something else. Pinned ones (`pin`) stay: font pages and the hint atlas sit on cells with other content.
- **Sampling**: nearest for cell fonts without margins (the picture step enables it for FONT16/FONT24, the game font for its pages) and for a sheet the size of its texel space; otherwise the preset filter.
- **Files**: `formats/texture/picture` reads PNG, BC7 DDS (`bc7_dds`, DX10 header with format 98/99 only) and TIM (a mod may put a TIM larger than the original at the disc path), detected by the first bytes; an unreadable file is named in the log with the reason.
- The store knows nothing about the GPU (`TextureSink`); test `tests/render/replacement_store_test.cpp`; file reading `tests/png/picture_test.cpp`.
- AI upscaled textures (`texture_upscale`, section 12): the scene's map textures and the glTF characters read the upscaled copy of the imported PNG, not this store; a TIM read into video memory with no mod picture (2D screens, paper maps, examine pictures, effect sheets) gets its imported PNG, and from the moment the cache has it the upscaled one, put into this store over its place through palette row 0 (`engine/app/loader/upscaled_pictures.h`, `ImageStepHost::vram_upscaled`), except fonts and pictures whose palette mixes STP and solid colours. A mod's picture always wins and is drawn as it is: a TIM a mod replaced never gets the upscaled picture, and an upscaled copy is used only for the bytes of the imported PNG. Textures with lettering (`gamedata/config/texture_upscale.json`) are scaled with a Lanczos filter instead of the network, whole or in rectangles. Each picture changes as soon as its file is written (`sh::scene::refresh_textures`, `take_refreshed_textures`: the renderer drops only those copies). The scene gives an upscaled map texture a mip chain (`mip_levels` in `area_cells.h`, `TextureDesc::mipLevels`, `CommandList::uploadTextureLevel`, implemented by every backend: a level the device does not hold reads as transparent and the surface vanishes at a distance; coverage and the STP class by majority per level) and `scene.frag` picks the level from the screen footprint, each level filtered with its own UV box, two levels blended for the linear filters; every other texture has one level and samples as before. The textures a frame's new meshes need are read and decoded together, the decoding and the mip chains on several threads (`sh::scene::prefetch_textures`), so entering a map with upscaled pictures does not decode them one after another in one frozen frame.
- There are no DuckStation-style texture packs (`texturepacks/`, lookup by VRAM upload hash) and no texture dumping.

## 4. Engine frame and draw order

`sh::frame::Frame` (`render/frame/frame.{h,cpp}`) is the list of everything drawn in a video frame. An entry (`Entry`) is a reference: a kind and an id in the command store.

| `Kind` | What |
| --- | --- |
| `Draw2D` | id in `sh::draw2d::frame_commands()` |
| `Draw3D` | id in `sh::draw3d::frame_commands()` |
| `Scene` | scene item code: 0 — map cells, n + 1 — posed mesh n |
| `Capture` | pack what has been drawn into the VRAM rectangle `Entry::rect` so that later draws can read it |
| `Area` | change the draw area to `Entry::rect` |

Order key `OrderKey {Layer, slot}` and the display buffer the lists are built for (`set_buffer_source`). Layers: `World` (scene, 2048 slots), `Overlay` (over the scene, 16), `Inset` (item close-up on the pickup screen, 512). Submission: `submit`, `submit_keyed`. Rules (they follow the original ordering tables):

- a layer is drawn by slots from top to bottom (`take_layer`); entries of one slot from the last submitted to the first;
- `Inset` is drawn inside world slot 0 after `link_inset`: first the slot 0 entries submitted after linking, then the inset slots, then those submitted before it; `clear` drops the link;
- an entry lives until it is drawn, but no longer than four `end_frame`s;
- layer depth is `slot_depth`: a linear view scale with `set_view_z_shift`; inset slots continue the world's count past its bottom;
- `resolve_scene_captures` (`render/gpu/frame_draw.cpp`): before the world is drawn, an area outside the display buffers (x ≥ 320) is declared a scene redirection, and the next on-screen area becomes a `Capture` entry of that rectangle. Such an entry shifts the layer depth by a slot (`steps_down`), like a closed bucket in the original.

`draw_frame_entry` (`render/gpu/frame_draw.cpp`) turns an entry into vertices and splits of `SplitBuilder`: 2D and 3D commands through `sh::draw2d::emit_stream` and `sh::draw3d::emit_stream`, scene and capture items into their own splits. The world key from a drawer's bucket is `world_order_key(bucket)` (`render/game_view.h`, clamped to 1..2047).

## 5. Drawer commands and projection

### 5.1 2D (`render/draw2d`)

`sh::draw2d::Command`: `Sprite` (1:1 texture rectangle), `Fill`, `Polygon` (triangle or quad, flat or Gouraud, textured or not), `Line` (2–4 points), `DrawMode` (page, dithering), `DrawArea`, `Mask`; `TexturePage`/`Palette` decode the word losslessly. Field semantics follow the original 2D rasteriser: coordinates are pixels from the draw offset, 16 bits with overflow; texels are 8 bits within the page; colour 128 is the texture unchanged; a semi-transparent command blends only texels with the STP bit, by the page's mode. `VertexFog` is per-vertex fog of a Gouraud polygon: drawers that wrote the colour as a 32-bit word with the primitive code put the code into the top byte of the colour word of vertices 1–3, and this is visible in the frame (shading of the options menu entries). The command carries these bytes explicitly.

`draw2d_stream` builds the stream's triangles: a rectangle is TL, BL, BR, TR, then two triangles; a quad is (0 1 2) (1 2 3). A triangle wider than 1023 or taller than 511 pixels is not drawn (the GPU rule, relaxed by `widescreen_edge_fix` and `psx_poly_size_cull`, 7.1). Submission: `draw2d::submit(command, key, depth_max)`; `display::draw_now` draws a command immediately (the paper map screen).

### 5.2 3D effects (`render/draw3d`)

`sh::draw3d::Polygon` holds the corner screen positions computed by the game and carries explicitly: the unrounded corner projection and view depth, the corner position in view space with the projection constants (flashlight, near clipping), depths `sz[4]` with their source (order against the scene), alpha, "affine" and "no flashlight" flags, and for meshes the corner normals and per-corner fog. Submission: `submit_projected` (a polygon with its own projection), `submit_placed(polygon, depth_history, key)` (depth from the last four depths of the geometry module), `submit`.

### 5.2a Bullet holes (`render/decals`, `bullet_decals`)

A player shot that ends on world geometry (not on a character) leaves a hole: up to 64, the oldest are evicted, a map change clears them.

- **The surface is the drawn one, not collision.** Collision has no normals or textures, so the decal looks for what is visible: `sh::scene::solid_surface_on_segment` (`render/scene/surface_query.{h,cpp}`) casts a segment along the shot around the point where collision stopped the bullet (0.5 m before it to 1 m past it) through the triangles of the last frame's cells and world objects (`placed_cells`, `placed_objects`) and returns the first solid point: its normal (towards the shooter) and the triangles of the same plane within 48 units. A triangle is skipped where its texel is cut out (alpha 0: fence, grate) or, for a translucent material, blended (STP: glass). Nothing solid on the segment — no decal.
- **The decal does not leave the surface.** The decal square lies in the hit plane (axes along and across the wall; on a floor, world X and Z). If the plane's triangles cover it entirely (7×7 probe grid) it is drawn as one quad; otherwise (edge, corner, a pillar narrower than the decal) only its parts on the surface remain: the square is clipped against each triangle (Sutherland–Hodgman) and drawn as triangles; a part whose centre is already covered by another (a poster on a wall) is dropped.
- **The picture is not a file.** `bullet_hole_sheet(seed)` (`bullet_hole.{h,cpp}`) builds a 256×256 sheet of 16 different 64×64 holes: a punched core, a chipped crater with bare material (16 radius sectors, 1–3 large chips), 2–5 hairline cracks, a soot halo; each cell fades to its edge so neighbours do not bleed under filtering. A texel is data for the decal program, not a colour: `R`, `G` — normal tilt along u and v (128 is flat, from the hole's height field), `B` — the share of the wall's light the point keeps (128 — all of it: the decal only darkens), `A` — coverage. The sheet lives in the hi-res replacement pool slot `HIRES_POOL_DECAL_SLOT` (255) and is registered again after a map resets the pool.
- **Hit look**: `bullet_hole_look(x, y, z)`: a hash of the hit point picks the sheet cell, the rotation on the surface, the size (0.8…1.35 of the nominal 7.5 cm half width) and mirroring. The game RNG is not touched: the same hit looks the same in any run and replays do not change.
- **Depth.** Decal polygons lie on the surface (lifted 4 mm); corners are projected by the frame view (`ViewProjection`); the polygon carries their exact projection and its own view depth (`DepthSource::Actor`). The renderer tests it against the scene depth buffer without writing (`plan_split`: a blended split with `ppw > 0`), so a wall, corner, rail or character in front hides it. The map is written `kWorldDepthBias` (8 units, ~3 cm) deeper than its plane along the normal (6.2, item 4), so on its own wall the decal wins without its own offset. For the same reason depth cannot tell a decal from the back side of a thin wall; such a decal is dropped by the sign of the normal in view space.
- **Light, fog and darkness come from the wall.** The decal is not lit itself: it is "painted" on what is already in the render target. The flag `draw3d::Polygon::surface_decal` sets `geom3d = 2` on the vertices (`rhi::kGeomSurfaceDecal`); the fragment shader (`prim_batch.frag`, branch `decal` of the RGBA program) samples the texel with its own bilinear fetch (`DecalSample`, regardless of `texture_filter`), without the 0.5 alpha cut, and writes black with alpha `coverage × (1 − keep)`. Ordinary alpha blending gives `wall × keep` where coverage is full: vertex light, the flashlight (any style), shadows, darkness, tint and post-processing of the wall stay the same, and the decal can only darken — it is never brighter than its surface. `keep = min(2·B, 1) × relief`. Relief under the flashlight is the ratio of the lighting of the perturbed normal (tangent basis from position and UV derivatives, cotangent frame) to the flat one, at most 1, weighted by the flashlight's share of light at that point; without the flashlight, a constant soft top shadow so the crater reads in map light too. Fog lies over the paint: alpha is multiplied by `1 − fog` (the corner fog byte from the ramp at its depth, `fog_ramp_at` + area density; with `soft_fog`, by fragment depth, P3); in full fog there is no decal.
- **Why not paint the wall texture.** World textures are shared atlas tiles repeated across walls and rooms, so a point painted into the texture would appear on every repeat; hi-res and mod textures are not ours either. Maps have no separate unwrap for paint (like lightmaps). The quad over the wall gives the same result as a painted texture: a multiplier on the already lit wall colour.

Tests: `tests/render/bullet_hole_test.cpp` (sheet, hit look), `draw3d_stream_surface_decal_is_marked_for_the_decal_program`.

### 5.3 Geometry and projection (`src/engine/math`, `sh::math`)

- `fixed_geometry.{h,cpp}` — the game's fixed-point math: perspective projection, matrix × vector with offset, depth cue colour blends, rotation matrix builders. Results match the original geometry coprocessor bit for bit (product shift 12, 16-bit saturation, overflow flag word).
- `geometry_state.{h,cpp}` — geometry state between calls (`sh::math::geometry()`): loaded view, light and light colour matrices, background and far colour, screen (distance, offset, depth cue), the view stack and the history of the last projections (SZ0..SZ3, SXY0..SXY2).
- `view_projection.{h,cpp}` — `ViewProjection`: the projection a drawer uses to project by itself (view Q12 + translation, precise camera; screen `ScreenSetup`), with a history like the module's. View building operations: `multiply_rotation`, `set_translation`, `requantize`, `transform`, `rotate_long`, `project`, `project3`, `project4`, `ordering_depth`. The precise camera of a product is quantised the same way as the original latch.
- `precise_projection` (`project_precise` → `PreciseVertex`) and `precise_capture` (`sh::math::capture`) — the precise path (`use_pgxp`). `precise_capture` keeps twins of the game's matrices: the unrounded values known to whoever built the matrix. A twin is found three ways: by record address (`note_rotation`/`note_translation`, `rotation_of`/`translation_of`, `copy_rotation`, `forget_*`), by the integers themselves for the camera and matrices built from it in the frame (`set_camera`, `register_derived`, `register_camera_point`, `register_camera_turn`, `derived_*`), and for the view loaded into `GeometryState` (`rotation_loaded`/`translation_loaded`, `current_*`). A twin is trusted while the record's integers are the ones it was recorded for, and until the end of the frame (`end_frame`); a record without a twin gets the best available for its numbers (the camera twin or a derived matrix, otherwise the numbers themselves). While precise vertices are off, nothing is recorded or found. Test: `tests/world/precise_capture_test.cpp`.
- `src/engine/effects/drawer_projection.h` (`DrawerProjection`) — one effect drawer's projection over the game state: continues the module's history, restores it at the end and around foreign code (`around`), places a polygon by key (`place`), gives precise corner records (`corner_records`).

### 5.4 Lua: `sh.render.*`

Screen effects of cutscenes and puzzles (`frame_hold`, `held_clear`, `held_capture`, `world_redirect`, `tile`, `sprite`, `texture_load`, `fade_in_level`, `world_quads`, `panel`, the picture screen) are engine code: `src/engine/scripting/render_binds.{h,cpp}` and `binds/binds_panel.cpp`. 2D is `sh::draw2d` commands in frame layers and slots (world 1/2/2047, overlay 0/3/15); an area change is `Kind::Area`; world redirection and the held picture go through `resolve_scene_captures`. Lua: [modding/lua-api.md](modding/lua-api.md).

### 6.2 Scene frame

1. `Gfx_InGameDraw` → `draw_world`: at the first cell the world fog ramp with the cull depth and the bucket depth scale are set; cells that passed the load and window checks, and cell glows (`Gfx_BillboardDraw`), are put into the frame; the cell item goes into the farthest world slot.
2. World objects and the held item are items by key: group base (`ot_group`) + the model origin z >> (shift + 2). Characters are one item per material in the bucket the character's parts would go to, so the order against surrounding effects (the flashlight glow at Harry's chest, blood) is as in the original.
3. For a scene split `SplitRenderer` sets the ortho and viewport of the world draw area and passes a `View` with the same fog, flashlight and filter as the surrounding primitives.
4. Depth is shared with primitives: NDC z = 2·z/szMax − 1, W = view z. Every scene fragment (cells, items, poses, seams) writes its exact depth `gl_FragDepth = z/szMax` (`v_depth`, perspective-correct interpolation): rasterised depth, linear in view z, is interpolated across the screen and on a long floor or wall triangle drifts far from the surface, so it serves only for near-plane clipping. The map (cells) is written as if its plane lay `kWorldDepthBias` = 8 units (~3 cm, one slot of the original ordering table) deeper **along its normal**: the fragment takes the plane normal from view position derivatives, h is the eye-to-plane distance, and writes z·(1 + 8/h) (slope z/h at most 8). The margin is thus the same at any view angle: a foot, item, decal or wall prop within 3 cm behind the surface wins, while a corner, rim or wall farther in front of the prop hides it (the ball in the corner of the map1_s03 gutter). Why: the original put a polygon into a slot by its farthest vertex (`Gfx_MeshDraw`: `(z >> otShift) >> 2`, otShift 1 — 8 units per slot, slot base by model group) and linked world objects before cells, so within one slot an object was drawn over the surface it hangs on. The data relies on this: the map board in the hospital lobby (`MAP_HIDE`, group NEAR) sits 3 units inside the wall (group BACK0). Effects: `SceneDepth::Margin` — 32 units nearer than its point, `Exact` — `kWorldDepthBias` of view depth farther (`drawer::bind_scene_depth`, `drawer_projection.cpp`). Script panels (`render.panel`, the map4_s03 TV wall screens) are also `Margin` by their corner depths: a primitive without its own depth is compared at its ordering slot's depth, which is taken from the farthest corner. The scene loses early depth testing. 3D primitives of the world pass test the scene depth; translucent ones (snow, glow, water) without writing; 2D primitives are drawn without depth. szMax is the constant 2^18, also without PGXP (`use_pgxp = 0`).
5. Flashlight shadows (7.9): in the shadow pass the scene split draws the map, objects and characters (Harry included) into the two shadow map layers — depth of solid texels and transmission of blended ones; the scene reads it with PCSS against the receiver plane, primitives with PCF.

### 6.3 Map light (shader specification)

Map data is designed for per-vertex light; the module repeats the rules. Vertex colour = world tint × intensity / 128, then texture × colour / 128 (128 is unchanged), then fog.

- Mode 0 (no source): the tint shifted towards the far colour by (1 − darkness/4096) — a frame constant.
- Mode 1 (point source, the original flashlight): d = v − Lp; cone term sx = clamp(⌊−1024 + (L·d/4096)·q/65536⌋, −1024, 1023) + 1024, face term sy the same with n·d (n is the data's inward normal), q = 16/(|d|²/4096) in 16.16 saturated at 0x1FFFF, falloff dp = clamp(⌊DQA·q/4096⌋, 0, 4096); I = min(max(⌊(sx·sy + sy·⌊dp/16⌋)/32⌋ − 16, 0) + ⌊darkness/32⌋ + min(⌊sx/2⌋ + ⌊dp/4⌋, 48), Imax).
- Mode 2 (directional): I = min(⌊(max(L·n, 0) + darkness)/32⌋, 255).
- Without fog a lit vertex goes from the far colour to the tint by I·32/4096 (black when I < 8).

L is the source direction × intensity, Lp the position, DQA the falloff coefficient (atmosphere `sh::world::WorldAtmosphere`); all are transformed into view space. World objects are lit by the same rule (all `BG/*` and `ITEM/*.PLM` models have the "character light" flag at 0).

A translucent material blends only STP texels by its original mode (ABR): 0 — `B/2 + F/2`, 1 — `B + F`, 2 — `B − F`, 3 — `B + F/4`; added and subtracted texels go to black in fog; the material's other texels are solid. Such a material is drawn in two passes: solid texels in the opaque pass with depth writes; STP texels in the blended pass without writes (`Blend::Subtractive`/`AddQuarter` cannot be drawn otherwise: no factor leaves a texel solid). Solid texels must write depth, otherwise grates and blinds let primitives behind show through solid bars.

Where the mode comes from. Map cells, PLM and held items are always `additive`: the page byte in the LM on disc is zero and the game's loader sets the mode; the import writes it into `extras` (version 10). Item models (TMD) take it from the face's page word (all 12 translucent materials of `ITEM/IT_00x` are `average`). Characters: the type's mode (`blend_mode` in `character.json`) and map script edits (`npc.material_set`, `npc.transparent_set`): `gltf_chara` reads them from the model records (`model_blend_state`: the material's page byte and the faces' translucency bit — all on means the whole material is STP, all off means solid). 13 models have translucent faces; visible on Larval Stalker (CLD1, `subtractive`: a dark silhouette, map1_s00/s01, map6_s04), Ghost Child Alessa (TAR, `additive`: a glowing translucent ghost, map7_s01/s02), Ghost Doctor (DOC), Incubator and Bloody Incubator (MAR, BAR; MAR on Unknown 23 is `average`), Incubus (BOS), Little Incubus (LITL), Flauros (BFLU), Floatstinger (MTH, wings), Stalker (CLD2, `subtractive`).

### 6.4 Character bone light

`sh::world::bone_light` (`engine/world/bone_light.{h,cpp}`): mode 0 — `ambient_color` (world tint × map light, far colour black), mode 1 — `chara_light` (depth slope `light_depth_cue`, base 0), mode 2 — `scaled_light`; the light matrix is the first row, the colour matrix is the atmosphere's `light_color`, background × 16.

### 6.5 Seams, UV boxes and filtering by alpha class

- **Seams.** Map data has open edges (gaps of 1–4 units and T-junctions) that the console hid by rounding vertices to 320×240 pixels. `add_seams` (`area_cells.cpp`) finds edges of a cell's opaque triangles without a neighbour (compared on a 1/16-unit grid) and writes them as lines `CellMesh::seams` at the end of the index buffer. `SceneRenderer::draw` draws them before the triangles: pipeline `scene seams`, LineList, LEQUAL with depth writes, five passes with offsets 0 and ±1 pixel. Triangles at the same depth cover them; the edge colour remains only in the gaps. Cost: open edges against fog are at most one pixel thicker.
- **UV box.** The import writes UV as (u + 0.5)/w; the console shows texels lo … hi − 1. `stamp_uv_boxes` gives each material triangle a UV box (`CellVertex::box_*`, attribute 4, `flat`; a vertex with different boxes is duplicated); `scene.frag` (`SampleTexture`) samples only inside the box, `floor` with the filter off. A mod material without `extras.png` is sampled by its own UV. For primitives the box is set in the vertex (`PrimVertex`), the upper bound one texel less than the maximum UV.
- **Filter.** Hardware LINEAR would mix the alpha of the classes (255 solid, 128 STP, 0 hole) and give a light outline around cutouts. Instead four `texelFetch`: holes give no colour, a cutout edge uses nearest sampling (coverage < 0.5 is a hole), the STP class goes by weighted majority.
- **`centroid`** on scene and primitive UV: with MSAA a sample at the pixel edge would otherwise extrapolate UV into a neighbouring atlas cell.

### 6.6 Overlay layers (`CellRange::layer`)

Road markings, manholes, painted shadows, posters and signs lie in the plane of their surface or 1–12 units in front of it in the data. The depth buffer is linear in view z and the rasteriser interpolates depth across the screen, so a triangle's written depth is not less than the true one and differs more the longer the triangle is in depth. Two layers of one plane split into different triangles would get different depths in one pixel, and the overlay would lose the test in patches depending on the camera angle (the map2_s02 bridge, map2_s04 posters). On the console the ordering table set the order.

- **Detection**: `layer_overlays` (`area_cells.cpp`) when reading a cell and a library model. Triangles of one orientation overlapping in the plane (a shared border does not count) and at most 24 units apart form a stack; the top one is the one in front. Within one plane (up to 0.5 units) the top one is the one whose model the game sorted from a nearer ordering slot (`ot_group` of the model in `<CELL>/models`: groups 0…5 → slots 2, 0, 4, 33, 66, 99); with equal or unknown slots, the smaller by area (area of the model and material on the plane, then of the connected piece). One material of one model over itself is the same surface (cells repeat instances in place) and gives no layer. A triangle's layer is one more than the highest layer below it, up to `kMaxOverlayLayer` (7); only triangles that cover something are raised.
- **Drawing**: material ranges are split by layer. Layer 0 is drawn normally. Higher layers use the `kOverlay` pipeline: the same `scene.frag` with `SH_SCENE_EXACT_DEPTH`; the fragment writes `gl_FragDepth` — the depth of its point on the plane (`v_depth`, interpolated over the surface), nearer by `kOverlayLift` (0.25 units) per layer. The base also writes exact depth, so an overlay beats its surface at any angle while anything in front hides it as usual; the top layer (7 × 0.25) stays within the map margin (8 units along the normal, along the ray at least ~0.7 of that in view depth), so props and bullet holes on an overlay beat it. Layers do not depend on PGXP, MSAA or the preset: they are mesh data and scene depth. In the shadow map layers are drawn without lift.

### 6.7 Water surface

A cell material without a picture (`CellMaterial::unpictured`; in the area file extras, `material` with an empty `tim`) named in `scene::water_surface()` (provided by the water host from `gamedata/effects/water.json`, block `surface`) is drawn by the water branch of `scene.frag` (`u_mat.y = 2`, block `SceneWater`, sampler `s_reflect`). The meaning of the numbers is in the file's `description`.

- **Light.** The water albedo is `lit_color` times the wave pattern; then the usual material path: per-vertex map light, per-pixel flashlight of both styles, flashlight shadows, fog. Water is visible only where light reaches and is lit like the floor next to it in all presets. `base_color`, the reflection and the lamp spot are added to the result.
- **Waves.** `WaterHeight(p, t)`: the sum of three bent sines in world xz (view → world matrix in the block): long crests along x, smaller ones diagonally and a slow swell. Time is the 0..1 phase of the water clock (`scene::set_water_phase`); each term makes a whole number of turns per cycle, so the cycle closes without a jump. The slope is two finite differences; waves narrower than a few pixels (`fwidth`) fade to the mean, so there is no shimmer in the distance. The quality level (below) may keep one or two terms, compute waves at grid square centres, step brightness and phase, and with zero distortion skip the slope entirely.
- **Reflection.** Before the frame's cells, `SceneRenderer::reflect()` draws the posed meshes (characters) mirrored in the water plane (`v' = v - 2 (n·v - d) n` in the view matrix; the flashlight uniforms are mirrored too, shadows off) into its own RGBA8 + D24S8 target with `reflection_lines` rows of the quality level (width by the frame), with the frame's projection. The shader reads it at the fragment's screen position (`u_wProj`) shifted by the wave slope, with one, three or five samples by `blur` (`blur_taps`); the result is multiplied by `tint * strength` and added. With `reflection_filter` `nearest` the blur is off and the picture's pixels are visible; with `reflection_lines` 0 there is no pass and characters are not reflected. The plane height is the mean height of the material's vertices in the cell plus `plane_offset`. The pass opens only when the frame has a cell with the water material and at least one posed mesh; `SplitRenderer::draw_scene` closes its pass, calls `reflect()` and opens it again. Walls and world objects are not reflected.
- **Lamp spot.** The frame lamp (`Frame::water_lamp`, strength `water_glow`, reset at the end of the frame) is mirrored in the plane and projected; around its point a soft spot of radii 24 × 48 frame units times `glow.size` is drawn, `glow.color` at the edge and lighter towards the middle; waves break up its edge (at a level without distortion the edge is smooth and the spot's brightness steps by `color_steps`).
- **Quality levels.** The key `water_quality` (`auto` / `low` / `medium` / `high`; 7.1) selects a row of `surface.quality` in `water.json` (`render::graphics().water_quality`, 0–2); `auto` is the preset's level: `original` — `low`, `enhanced` — `medium`, `high` and `ultra` — `high`. The level's numbers go into the uniform block (`u_wLevel`: wave layers, grid step, colour steps, sample count; the phase is stepped and distortion multiplied on the CPU); shader branching is by uniforms, uniform for all pixels of a call. `low` is the console look and the cheapest: one wave layer on a grid of 14 squares per metre, 5 brightness steps, 64 cycle steps (15 wave pictures per second), no distortion (one wave evaluation per pixel instead of three), no reflection pass, a stepped lamp spot. `medium` — three layers, distortion, a 240-row reflection with three samples. `high` — the same with five samples.
- **Cost.** CPU: one uniform block per `draw()` call and the plane search over the frame's cells. GPU per water pixel: `low` — 2 sines, no reflection samples or pass; `medium` — 21 sines (three wave evaluations of 7) and 3 samples; `high` — 21 sines and 5 samples; the reflection pass at `medium` and `high` is 7 draw calls into a 320 × 240 target on `map5_s00`. The level difference is within frame time noise on a fast GPU; it matters only on a weak GPU.

### 7.2 Presets

The preset is written into the config before the file is parsed (`RenderPreset_Scan`, `RenderPreset_Apply`; table in `src/render/settings/render_preset.cpp`), so a table key written in the file overrides the preset only for itself. The same preset becomes the snapshot of defaults for "reset" in the menu. Choosing a preset in the menu (Options > Graphics > Quality Preset) comments out the preset keys in the file and sets Options > Lighting to Classic (`original`) or Modern. No table key changes logic, timing, fog distance or frame composition.

Above `enhanced` (the default, unchanged) each step adds the next most visible feature (section 14): `high` the HDR frame with the soft tonemapper and a faint bloom, TAA, ambient occlusion and the map lights; `ultra` every other feature without ray tracing at its best; `ultra_rtx` ray tracing with all its effects (no other preset but `ultra_rtx_upscaled` has it). `ultra_upscaled` and `ultra_rtx_upscaled` (menu: "Ultra+AI", "Ultra RTX+AI", the help line marks them experimental) are the same two with the experimental model and texture upscaling, which not every player likes, so the plain ones leave it off. Every feature keeps its own row, and the preset row reads Custom once one differs. The features of the native Vulkan renderer are written by every preset alike; under GL and SDL3 GPU they do nothing (their rows are hidden, the preset row's help says so), and a GPU without ray tracing skips the `rt_*` keys (the menu steps over both Ultra RTX presets there). MSAA and TAA never meet: the native backend has no multisampled targets, so `msaa` serves GL and SDL3 GPU, `upscaler` the native backend. Both upscalings are experimental: their Options group is "Models and Textures (experimental)" and their help says so. The two `_upscaled` presets take `texture_upscale` x2, not x4: x4 tends to look smeared, so the row's help does not recommend it. They take `model_upscaling` = `tessellation`, not `mesh_shaders`: both draw the same surface (they differ only in the inner triangulation, 7.11), the map's curved surfaces go through the tessellation stages in either mode, and far more GPUs have tessellation than `VK_EXT_mesh_shader`, so the preset reads the same everywhere. While texture upscaling runs the preset row and the AI Texture Upscaling row show the progress (without the `sh-upscale` tool beside the game the originals stay).

### 7.3 Shader rules

- **Deband.** Without the original dithering, fog gradients and the flashlight falloff band in RGBA8. A static interleaved gradient noise of ±0.49 of an 8-bit step: a black additive texel is not lifted, a flat colour changes by at most one level, frame feedback (5 bits) is not affected. Only with dithering off and on frames with the world.
- **Soft highlights.** Per-pixel flashlight light is the only source above 1.0. Above the 0.85 knee the maximum channel follows an exponential shoulder to 1.0 and the others scale the same way (hue is preserved); below the knee and without the flashlight nothing changes.
- **Beam edge**: `smoothstep` between the inner and outer cosine; changing the cone shape would change the lit area.
- **Dither cell**: 8 pixels with a target width from 480, 4 in a target of the original size (1 pixel per matrix element, as on the console).

### 7.4 Soft fog (`soft_fog`)

The original fog is hard: the 128-byte ramp (a gamma curve) is sampled without interpolation, vertex fog is quantised to 7 bits and interpolated linearly across the face, density is linear up to full opacity. `soft_fog = 1`:

- **P2** — a knee at full fog: linear up to 0.85, then `0.85 + 0.15·(t − t² + t³)` up to 1.0 with zero slope. Where anything is visible through the fog, the density is the original's. An exponential curve fogs the middle too much (0.3 → 0.78).
- **P3** — per-fragment fog: if every vertex fog byte of a triangle is the ramp at its own depth, the fragment recomputes fog from its perspective-correct depth with ramp interpolation (`FogAmountAtZ`). Vertices with special fog stay per vertex.
- **P4** — fade at the world cull boundary: fog is brought to full over the last 15 % before the cull depth (`smoothstep`) so that with `fog_strength < 1` the world does not end at a hard edge. Frame composition does not change.

Fog is not part of replay dumps; the option is purely visual.

### 7.5 Precise vertices and `smooth_models`

Causes of model jitter on the original: (1) every vertex is rounded to a whole 320×224 pixel (4 pixels at 1280×960) — fixed by `use_pgxp`; (2) bone transforms in fixed point: animation interpolation truncates translation to Q8 and rotation to Q12, each hierarchy level truncates again, the root is the character position in Q8; vertices jump by 0.15–0.2 original pixels — fixed by `smooth_models`; (3) the camera in whole angle units (0.088°) moves the whole picture — fixed by the camera twin (below).

`smooth_models` (`src/render/precision/pc_smooth_xform.{h,cpp}`) is a double-precision twin next to the integer logic: bone animation records the unrounded rotation and translation of a bone keyed by the integers just written (if the game changes the bone itself afterwards — IK, head turn, script — the key does not match and the bone is drawn from the integers); the character root gets a fractional position; the hierarchy and camera are composed in double and registered as the precise camera of the view matrix. If the twin differs from the integer matrix by more than 48/4096 in rotation or 24 units in translation, it is not registered. Logic and all integer values do not change. There is no inter-frame interpolation: logic runs every frame. Key: `sh::render::precise().smooth_models`; the "draw from twins" check is `sh::render::smooth_view()` (needs `use_pgxp`).

**Camera twin.** With `smooth_view()` all draw paths use one unquantised double camera, so nothing shifts relative to anything else (`src/engine/camera/precise_view.{h,cpp}` → `sh::math::capture::CameraTwin` in `precise_capture`):

- built after every `vcExecCamera`: position is the Q12 `cam_pos` before truncation to Q8, rotation is `Ryxz(base)·Ryxz(offset)` in double; angles follow the integers at the mean speed of the last 4 frames and are held within ±0.75 angle unit (≈0.07°) of the integer camera, with no lag;
- if the twin differs from the integer matrix by more than 24/4096 or 1.5 units, the integer camera is used; with a scripted camera (look-at), first-person view bob and the head view, the twin equals the integer camera, but it is still one for all paths;
- the twin is keyed by the integer world→screen matrix (`ViewSystem::set_world_screen`); matrices built from the camera in the frame (`world_screen_at`, `view_matrix`, `frame_at`, `drawer::move_to`, effect rotations) are registered by content and found by `sh::math::capture::derived_rotation` / `derived_translation`;
- it is read by cells, objects and the held item (`world_scene_source`), characters (`gltf_chara`, `pc_smooth_xform`), effects (`ViewProjection` with `PreciseSetup::exact_products`, `EffectView`), decals, particles, water, the flashlight cone (the shadow map is in the same view space);
- a character bone's view (`gltf_chara.cpp`, `store_bone`) is always "camera twin × the bone's world transform" in double. The world transform is the `smooth_models` twin if it agrees with the bone's integer world matrix (48/4096 in rotation, 24 units in translation), otherwise the integer world matrix itself (also for a scaled model). The bone is not checked against or reverted to the integer view matrix: the integer look-at camera is 1–3 angle units coarser than the twin, and such a check makes models far from a free camera jump between the two while turning;
- the free camera (`Pc_FreeCam_Apply`) reports its unrounded eye (`set_free_camera_view`) before `view_look_at`: the twin is published while the view system accepts the look-at and must find this frame's eye;
- the model's translation relative to the eye (`view_matrix`) is computed at full width, without the 16-bit `compose` register: a model farther than 128 m from the camera does not appear at a wrapped place; character vertices with view depth above 65535 (256 m) are not drawn, nor is the flashlight glint (`WaterEffects::frame`);
- logic, replay dumps and the `original` preset do not change (`original` frames match bit for bit);
- per-frame shots for such measurements: `sh_replay.py run --shots DIR --shots-from TICK`.

### 7.6 Widescreen

All extents of the visible area (glow and darkening rings, overlay squares, billboards, the far limit, the 1023-pixel threshold for large polygons `precise().poly_size_wide_scale`) are computed from the target and window size, not from 4:3 or 16:9 constants. Checked on 4:3, 16:10, 16:9, 21:9, 32:9, 48:9 and portrait windows for 3D and subtitles; menus and the inventory at 32:9 and portrait are not checked. Fixed-angle cameras in Hor+ are corrected by the camera table.

### 7.7 Culling (`culling`)

The "object on screen" check read by enemy AI, events and Lua (`Vw_AabbVisibleInScreenCheck`, `entity.aabb_visible`) is always the original: the game screen plus 2 units in raw projection coordinates, without window, `hfov`, `vshift` or margin corrections. Window size, preset and `culling` do not affect it.

`culling` affects drawing only:

- the second point of the cell window (`render/world/world_frame.cpp`): `original` with fog on places it by the camera (up to 9 m ahead, at most 16 m from the player), `modern` by the player's direction;
- fog cull distance (`WorldAtmosphere::fog_cull_distance`): in `modern` with `fog_strength < 1` it grows by `1/fog_strength` (at most `draw_distance_pct`, `sh::world::mesh_far_limit`).

The scene draws all window cells; it has no separate frustum culling of models. The "whole town" mode (`whole_map_exteriors`, needs `use_pgxp`) and the debug camera keep all outdoor cells resident. Log: `[CULLSTAT]` (mean frame volume, mode, map), `[PKTARENA] OVERRUN`.

### 7.8 MSAA (`msaa`)

With `msaa` 2/4/8 `Targets` keeps a multisample pair of RGBA8 colour + D24S8 (`TextureDesc::samples`) next to the single-sample scene texture. The count is `present::msaa_sample_count`: 8/4/2, capped to `Caps::maxSamples` (GL: the minimum of `GL_MAX_SAMPLES`, `GL_MAX_COLOR_TEXTURE_SAMPLES`, `GL_MAX_DEPTH_TEXTURE_SAMPLES`); the chosen count is logged once per change: `[GPU] MSAA: 8x on the scene target (asked 8, device max 32)`. If the pair cannot be created, 1 sample remains with a warning. Changing `msaa` in the menu or via the preset rebuilds the target on the next frame (`Targets::needs_resize`), like `render_scale`.

- Drawn into the pair: primitive splits and the glb scene (`for_split` → `draw_color()`/`draw_depth()`, `begin_draw` before the pass), frame and depth clears. The shadow map, offscreen VRAM area redirection, feedback captures and the post pass stay single-sample.
- Only the single-sample texture is read, through `Targets::resolved(cmd)`: frame feedback captures, the freeze frame, the post pass and output, the `shot` screenshot. Resolve (`CommandList::resolveTexture`, GL `glBlitFramebuffer`) happens only if the pair has new drawing.
- Direct writes into the single-sample texture (clear bars via blit, freeze frame display, the FMV frame, the overlay) are marked by `wrote_resolved()`; the next `begin_draw` copies it back into all samples of the pair with the `ms_seed.frag` pass (full-screen triangle, `texelFetch`). The overlay (console, debug) is drawn into the single-sample picture over the finished world.
- `foliage_edge = 2` enables alpha-to-coverage (`BlendState::alphaToCoverage`, a bit of the `PrimPipelineKey` key) only on passes into the pair; on single-sample targets it acts as 1.
- STP modes, fog, precise vertices and shadows work as without MSAA: the shaders are the same, `centroid` on UV keeps samples inside the atlas cell.

### 7.9 Flashlight shadows

They work in both per-pixel styles (`flashlight_mode` 1 and 3); `flashlight_mode` 0 (per-vertex light) has no shadows.

- **Map.** A perspective from the flashlight lens (`post::buildShadowLight`): the angle is the active style's cone with a 6 % margin (for Modern, together with its faint halo past the outer edge, `kModernSpillCos`), at most 166°. An object outside the cone shades nothing inside it, so no texels are spent on darkness.
- **Two layers** (`ShadowPass`, one pass): D24S8 depth for solid texels (cut by texture alpha: fence and grate holes let light through; for a translucent original material, its solid texels — grate bars and window frames); RGBA8 colour for transmission of blended texels (`Layer::ShadowTint`, multiplicative) with the distance to the nearest such surface in alpha (`min`, 8 bits from the far plane). Transmission by the original mode: mean (`Mean`) — 0.5, subtract — `1 − texel`, alpha blend — `1 − alpha`, add — `1 − 0.45 · luminance` (quarter — `1 − 0.12 · luminance`): glass and haze dim the beam rather than block it. A receiver nearer than the surface (with a margin of two alpha steps) is not shaded.
- **Casters.** Map cells, world objects, characters, Harry and the item in his hand. The source is the `Torso` bone plus the `light_rigs.flashlight` offset (`gamedata/effects/map_lighting.json`): a point 4 cm in front of the chest, so the body behind it does not block the beam; the weapon arm in the aiming stance passes in front of the lens and gives a soft shadow at the beam edge. Console `shadowplayer 0` turns off Harry's shadow.
- **Sampling** (`scene.frag`, `FlashlightShadow`): PCSS. Blocker search over the disc the lens (radius 9 units) sees around the receiver; penumbra width `lens · (receiver − blocker) / blocker` — sharp at contact, wider with distance; at least 1.25 texels and at most 0.02 of the map. The Vogel disc is rotated per pixel by static screen noise (the grain does not crawl as the light moves); each filter sample is a bilinear comparison of four texels. The comparison is against the receiver plane (screen derivatives, limited slope); the bias is a constant distance along the ray (1 unit + 0.5 % of the distance; `shadowbias` scales it), so far shadows do not detach from objects. `shadow_filter` 0 / 1 / 2 sets the search and filter sample counts: 8 + 12, 12 + 20, 16 + 32. Pixels the beam does not reach (less than 0.001 light) skip the shadow.
- Effect primitives (`prim_batch.frag`) read the same map with the PCF kernel (2×2 / 3×3 / 5×5) without the transmission layer; `shadowfade` acts only there.

### 7.10 HDR frame, tonemapper, bloom, HDR10 (`hdr_frame`)

Native Vulkan only (`Caps::floatTargets`); under GL and SDL3 GPU the Options row says why and the keys do nothing. Decisions in `src/render/post/hdr.{h,cpp}` (tested in `tests/render/hdr_test.cpp`), passes in `src/render/gpu/hdr_pass.{h,cpp}` and `shaders/hdr_bloom.frag`, `hdr_resolve.frag`, `hdr10_encode.frag`; Options rows in `src/ui/menu/options_hdr.cpp`.

- **The frame.** `hdr_frame = 1` makes the scene target `RGBA16F` (`Targets::scene_format`; the freeze-frame copy follows it). Its values are those of the 8-bit frame — the console's colour, sRGB-encoded, 1.0 = white — only not clipped: the per-pixel flashlight and additive blending may pass 1.0. A float target that cannot be made falls back to RGBA8 for the run with a warning.
- **The contract for other passes.** Between the scene and `PostPass::present` the HDR target is the input and output of every pass that adds light (AO, volumetric fog, reflections): they draw into `Targets::scene_color()`. `HdrPass::resolve` is the only place that maps it to the display; its output (RGBA8, or RGBA16F in HDR10) is what the post chain (look filters, FXAA, grade, brightness) reads. When the resolve has nothing to do the scene target goes on as it is and the post pass or the present blit clips it, so neutral settings cost no pass.
- **Tonemapper** (`hdr_tonemap`): 0 clamp (the 8-bit picture; `soft_highlights` still rolls the beam off in the shader), 1 soft (the shader's soft_highlights curve as an operator of the whole frame: identity to 0.85 of white, an exponential shoulder above, by the brightest channel so colour is kept; the shader's own roll-off is then off), 2 ACES (Narkowicz fit on linear light, 0.6 exposure), 3 Reinhard (extended, on luminance, white at 4×). Only frames that draw the 3D world (`scene_frame`) are mapped: menus, the title and movies are clipped only, as on the 8-bit frame.
- **Bloom** (`bloom`, `bloom_threshold`): dual filter on a chain of up to 6 `RGBA16F` levels from half size down to 8 texels (5-tap down, 9-tap tent up, each level added onto the one above). Energy-conserving: the light above the threshold leaves its pixel and comes back spread (`c − k·excess + k·chain / levels`), so the sum of light is kept and nothing below the threshold (fog, darkness) changes. Default 0; 0.3 is a faint glow round the beam.
- **HDR10** (`hdr_output`, `hdr_paper_white`, `hdr_peak`; needs `hdr_frame`): when the swapchain is HDR10 (2.2a) the tonemapper's white becomes the peak in the frame's encoding, the post texture is `RGBA16F` and keeps values up to it, the present and the overlay are composed into an `RGBA16F` stand-in at window size, and `hdr10_encode.frag` turns it into PQ over BT.2020 (SDR white = paper white). ACES and Reinhard still map to SDR white there; only clamp and soft use the HDR range. The sharp-bilinear present intermediate stays RGBA8 and clips highlights.
- **Known differences with the HDR frame on** (all settings neutral): blending happens in half float, so values that the 8-bit target would round between primitives differ by ±1 step; a subtractive primitive can leave a negative value that a later additive one adds to (the 8-bit target clamps at 0 in between); the resolve clamps negatives at the end.

### 7.11 Model upscaling (`model_upscaling`)

**Experimental** (the Options group and the row's help say so). Characters, enemies, world objects (props, items in the world, the held item) and the curved surfaces of the map (barrels, pipes, pillars, pots, terrain) drawn as PN triangles (curved point-normal triangles), cut finer the larger they are on screen (section 13). Native Vulkan only (2.2a); `off` (the default) draws the plain path unchanged, and under GL or SDL3 GPU the Options row is locked with the reason. Flat walls and floors of the map stay exactly flat (below). Item previews of the inventory and pickup screens are not upscaled. Nor is a mesh a mod supplies: a character glb (`convert/models/...`, also one a `character.json` patch points at), a library of world objects or an area file found in a mod (`ShVfs_FindModConverted`, `ShVfs_FindModDataFile`; `CellMesh::from_mod`, `gltf_chara` `Model::from_mod`) is drawn as the mod made it, since an HD model has its own shape and PN triangles would round it a second time ([modding/assets.md](modding/assets.md#character-models); `tests/render/scene_test.cpp`).

- **Files**: `src/render/scene/model_upscale.{h,cpp}` (welding, patch normals, levels, the GPU side `ModelUpscaler`), `src/render/scene/shaders/scene_pn.glsl` (the surface), `scene_pn.tesc` / `scene_pn.tese` (tessellation), `scene_pn.task` / `scene_pn.mesh` with `scene_pn_data.glsl` (mesh shaders). The later stages include `scene.vert` as a library (`SH_SCENE_LIB`, generated as `scene_lib.glsl` without its `#version` line), so light and projection are one code.
- **Patch normals.** Vertices are welded where they are the same point of the model: characters by their skin influences (`gltf_chara.cpp`, so the weld holds in every pose), world objects by position. The patch normal of a position is the mean of the file's normals there (characters, turned by the dominant bone each frame) or of the faces around it (world objects: their file normals are set for the PS1 light, not for the shape). A position is a **crease** where the file's normals split or where a face around it turns more than 40° from that mean; an edge between two creases stays straight, so hard edges and box-like props stay hard. Every edge depends only on its two corners, and the evaluation adds an edge's terms in an order both triangles share: no cracks.
- **Map surfaces** (`pn_surface`, `SceneRenderer` `make_cell_patches`, made once per cell on first use). PS1 cylinders have 5 to 8 sides, so their edges are either straight lines or hard folds and per-vertex PN would leave them as they are; the map therefore gets its control points per **edge**, computed once on the CPU and written to the corners of every face of that edge, so two faces always share an edge's curve (no cracks, whatever normals one face uses). Faces are joined into smooth groups across edges they run in opposite directions where they fold under 30°, or under 75° where both are long strips along the edge (no wider than 0.75 of its length and 0.75 m: the sides of a barrel, a hexagonal pillar, a tree trunk; not the chamfer around a flat plaque or a roof ridge). A corner's normal is its group's mean, weighed by angle and squared area, so a large face keeps its plane against small bevels. A smooth edge bends by those normals (PN), except at a tip (a cone's apex: the normal leans over 50° from a face of the edge), where it takes its two faces' mean and stays sharp. A **hard** edge runs along both faces' tangent planes at either end (the direction `n_a × n_b`): a barrel's rim rounds with its sides while its lid stays in its plane. Open edges, edges of three or more faces and edges of pinned faces stay straight. Only a triangle with a bent edge becomes a patch; the rest of the cell is drawn by the plain pipeline from a second index list (per range: flat triangles, then the curved ones, whose corners are copied so each carries its own control points: two `vec4` per vertex in the storage buffer, `u_pnLevel.y > 0` tells the stages). A flat face next to a curved edge is a patch whose control points all lie in its plane, so it stays flat. **Pinned** (never curved, edges straight): overlay layers (6.6), the water material, and any bending patch an overlay lies on (within 4 units of its plane), so decals keep their exact depth and do not sink. Seam lines (6.5, open edges) stay where they are, since open edges stay straight.
- **Map levels.** Every edge is cut by its own length on screen at its nearer end (`scene_pn.tesc`: a function of its two ends only, so both faces cut it alike), 8 pixels a piece, up to the cell's most level; a straight edge stays one piece, so a patch meets its flat neighbour vertex for vertex; an edge wholly behind the eye is one piece, and a patch wholly outside the view (or the shadow map) is dropped. The cell's most level comes from `pn_levels` with its curved triangles' mean edge at the eye's distance to the cell's box, within 1.5 million triangles a frame; a far cell is drawn plain. The map always takes the tessellation stages, also when the setting is Mesh shaders (the mesh path has one level per draw). The shadow maps take the same patches at most level 4 (their outline matches the curved surface, so a concave curve does not shade itself).
- **Only the shape changes.** Colour (the per-vertex light of 6.3, the characters' bone light), fog, UV and the UV box are the corners' own, interpolated as the plain triangle interpolates them; transparency classes, blending passes, the shadow layers (the casters are upscaled too) and collision (CPU data) are untouched. Fragment lighting (the flashlight, map lights, the RT results) takes the surface's normal from its screen derivatives, so it sees the curve. The ray tracing BLAS keeps the plain triangles: RT shadows, reflections and bounce light see the original polygons (a difference of at most a few centimetres on a barrel's side). The frame blending turns the characters' patch normals with the camera.
- **Level** (1..16, 1 = the plain pipeline): per model, all its meshes alike — the mean edge length seen at the model's nearest depth, cut to about 8 window pixels; then, while the frame would make more than 1.5 million triangles, the largest level steps down (`pn_levels`).
- **Tessellation**: `scene.vert` with `SH_SCENE_PN` hands the view-space corner and its patch normal (storage buffer) on; equal spacing, every outer and inner level the model's level. **Mesh shaders**: a task invocation per triangle drops patches wholly outside the view (their control points' hull) and keeps the draw's order; a mesh workgroup per kept triangle cuts it into level² triangles on a regular barycentric grid (at most 153 vertices, 256 triangles) and evaluates the same surface. Both give the same image apart from the inner triangulation (ring pattern against the grid), which the linear interpolation of colour and UV does not see: on static props the two differ in 0.01–0.02 % of the pixels, the same as two frames of the same mode.

### 7.12 Ambient occlusion and volumetric fog (native Vulkan)

`render/rhi/vk_atmosphere.{h,cpp}` (shaders `render/rhi/shaders/atmosphere/`), driven by `render/gpu/atmosphere_pass.{h,cpp}`. Standard Vulkan compute only. On GL and SDL3 GPU, or on a device without compute on its queue or storage for `R16G16B16A16_SFLOAT`, the Options rows are locked and their help says why (`ui.options.atmosphere.vulkan_only`, `.unsupported`); the log has one `[GPU]` line.

- **When**: once per frame, at the end of the world layer (`display::draw_layer(World)` → `Renderer::end_world`), before the screen overlay layer, so the HUD, menus and text are never touched. The inputs are those of the frame's world scene draw (`SplitRenderer::note_world`): the scene target and its depth (made sampled while a setting is on, `Targets::set_sampled_depth`), the scene's projection, the frame block (fog colour and strength, flashlight, shadow matrix), the fog ramp and the flashlight shadow map. Nothing runs without a world scene draw, with MSAA, or with both settings off.
- **Ambient occlusion** (`ao.comp`): per pixel of the world's viewport, 12 taps of a view-space hemisphere estimate within `ao_radius` (96 units, 0.375 m) around the surface reconstructed from depth; the normal comes from the flatter neighbour on each axis. The composite smooths it with a depth-aware 3×3 mean.
- **Flashlight only lit, never occluded.** The scene target holds one colour per pixel, not the map light and the beam apart, so the composite recomputes the beam at the pixel (cone, falloff, one shadow-map compare, the same formulas as `scene.frag`) and fades the occlusion out where the beam lights the surface: `k = 1 − strength · (1 − ao) · (1 − lit)`.
- **Volumetric fog** (`inject.comp`, `integrate.comp`): a froxel grid of about one cell per 10 pixels (at most 192 × 108) and 96 depth slices, the first linear to 48 units, the rest exponential up to where the fog is complete (the ramp's end or the world's cull distance). Each froxel holds the flashlight's light at its centre (cone, falloff, one compare against the flashlight shadow map, a Henyey-Greenstein phase towards the eye with `fog_anisotropy`) times `fog_scatter`. Integration front to back: slice `i` scatters `T(start) − T(end)` of that light, where `T` is soft_fog's transmittance at view depth (ramp, strength, knee, cull fade). The fog's density along each ray therefore is the original ramp: the eye sees the same fog amount at every depth, and past the point where the fog is complete nothing more is added. Where the ramp gives no fog (interiors and the Otherworld have the fog off; their darkness is the map light's), the beam scatters in a faint haze of 5 % per metre (`kHazePerUnit`) that only adds light and dims nothing, so a dark corridor shows the beam too.
- **Composite** (`composite.{vert,frag}`), drawn over the scene colour with blend `src + dst · src.a`: `colour' = colour · k + fog · (1 − T) · (1 − k) + S`, `S` the volume at the pixel's depth (trilinear; the far end where nothing wrote depth). The occlusion darkens the surface but not the fog in front of it; the beam only adds light, so it cannot show anything the fog hides. Half an 8-bit step of noise is added where there is beam light, against banding.
- **Soft fog while it is on**: with `volumetric_fog` the scene shades with soft_fog's ramp (`fill_shade`), the one the volume reproduces. With `fog_scatter = 0` (and AO off) the composite adds exactly 0 and the image is the `soft_fog = 1` image.
- **Limitations**: no temporal reprojection of the volume, hence the coarse grid and some noise; the SDL3 GPU and GL backends have neither effect.

### 7.13 TAA, TAAU and the spatial upscale (`upscaler`)

Native Vulkan only, standard compute and graphics; GL, SDL3 GPU and MSAA lock the Options rows with the reason (`options_temporal.cpp`). Settings and the pure decisions (Halton jitter, render sizes, camera cuts, the reprojection matrix) in `src/render/post/temporal.{h,cpp}` (tested in `tests/render/temporal_test.cpp`); the pass in `src/render/gpu/temporal_pass.{h,cpp}`; the Vulkan side in `src/render/rhi/vk_temporal.{h,cpp}` with `shaders/temporal/`.

- **Where**: at the end of the world layer (`Renderer::end_world`), after the atmosphere (7.12), on the scene target as the HDR frame holds it (7.10): before the tonemapper, bloom, the post chain and the film grain. The screen overlay layer (HUD, menus, text, the console) is drawn afterwards at the output size. Off, nothing runs and nothing is jittered: the image is the one without the setting.
- **Jitter**: the world's on-screen scene draws get a sub-pixel shift on their projection (`ortho[12]`, `ortho[13]`; every scene path — plain, tessellated, mesh shaders, the water's mirror, ray tracing — projects through it), Halton (2, 3) with 8 phases at full size and `8 / scale²` (up to 72) when upscaling. PS1 primitives of the world layer (particles, sprites) are not shifted; the resolve treats them like the rest.
- **Smaller world** (TAAU, spatial): `Targets::set_world_scale` puts every on-screen draw of the world layer into the top-left `scale` of its viewport and scissor; the result covers the full viewport. Only frames that follow a frame with the world are drawn small (a 2D screen after a menu or a movie stays whole); a world layer drawn small without a world scene is scaled up spatially.
- **Motion**: a point that stands still is reprojected from its depth with the two cameras (`post::reprojection`) and the previous projection. Posed meshes (characters, enemies, the held item when it is a posed mesh) and world objects whose transform changed are drawn into an `RGBA32F` motion buffer from both positions (a posed mesh's previous counterpart: the same index with the same shape, else the first unused one of that shape, as the frame blending matches them), with their own depth buffer, and only where their depth is the scene's within max(24 units, 4 %) — tessellated surfaces bulge off their flat triangles. A mesh with no previous pose marks its pixels for no history; translucent meshes (`Blend` other than opaque, semi-transparent object materials) mark them reactive (at least half the current frame).
- **Resolve** (`resolve.comp`, TAA and TAAU alike): the nearest depth of 3 × 3 drawn pixels picks the motion; the current colour is a Gaussian (Blackman-Harris fit) of the 3 × 3 jittered samples around the output pixel's centre; the history (`RGBA16F` at the output size) is read with Catmull-Rom and clipped towards the mean of the samples' YCoCg box (min/max ∩ mean ± σ); blending in a range-compressed space (`c / (1 + max c)`), so the beam's light above white does not outweigh its neighbours; weight of the current frame 0.03–0.1 by how near a sample lies, more with motion (up to 0.25), at least 0.5 where reactive. History is dropped where the point was hidden in the frame before (history depth, `R32F`), off screen, behind the previous camera, and wholly at a camera cut (`post::cameraCut`: a jump of more than 2 m, a turn above 25°, another projection distance), a new map (the first cell changes), a frame without the world before (menus, movies, the title), a change of mode or size.
- **Spatial upscale** (`spatial.comp`): Lanczos-2 over 4 × 4 drawn pixels, held to the range of the nearest 2 × 2 (no ringing). **Sharpening** (`sharpen.comp`, all modes, `upscale_sharpness`): an unsharp mask held to the range of the four neighbours, so fog gradients and the beam's edge get no halo. The result is drawn over the full viewport, colour only (the target keeps its alpha).
- **Feedback effects**: a frame in which the game reads its own frame (`FeedbackPass::note_sampler_prim`, a mid-frame capture, a freeze frame) leaves the next 30 frames alone (no jitter, whole size, no pass), so the original's frame-hold and feedback blur are neither smeared nor read from a small picture; the frame that shows the effect first is already drawn and is passed through the spatial path when it was drawn small.
- **Debug**: `temporal_debug = 1` shows the motion (0.5 + 0.05 × pixels in red and green, blue the motion buffer's kind) instead of the picture.
- **Limitations**: the volumetric fog and the ray-traced denoiser do not use the motion; static frames converge but are not bit-identical (the jitter goes on); no MSAA with TAAU (2.2a).

### 7.14 Map lights, sun shadows, god rays and flake shadows without ray tracing

The raster path of section 10: the same data as `rt_lights` (2.2b: `gamedata/maps/<map>/lights.json`, `gamedata/effects/lamp_lights.json`), so the presets without ray tracing have the lamps, the match and the sun. Native Vulkan only; on GL and SDL3 GPU the Options rows are locked with the atmosphere's reason (`options_atmosphere.cpp`). Ray tracing stays the higher-quality path: with `ray_tracing` and `rt_lights` on and a traced frame, the scene shader takes the traced light and skips these terms.

- **Map lights** (`map_lights`, `scene.frag` `MapLights`): forward shading, no clusters: the split renderer hands the 32 nearest lights that can reach a point the fog leaves visible (`describe_lights`, as for the ray tracer) and the sun to the scene shader in the `SceneFrame` block (the water's block with the lights after it: SDL3 GPU has four uniform slots per stage). Each light is the ray tracer's unshadowed term: colour, a spot's cone, the modern beam's windowed falloff, the fog of the way from the light (`1 − fog(distance)`); the sun is dimmed by the fog between the eye and the point, so it is never crisp deep in the fog and never brighter than the overcast data allows. Lambert on the face normal, times the albedo and the original's light share (`1 − vertex alpha`), only ever added after the flashlight, so the original tint stays the floor. The map lights are unshadowed (no cube maps); the sun takes the shadow map.
- **Sun shadow map** (`sun_shadows` with `map_lights`, `render/gpu/sun_shadow_pass.{h,cpp}`): one orthographic 2048² D24S8 map along the sun, fitted to the smallest sphere around the eye and the view's corners at the fog's reach (`sun_shadow::fog_reach`: where the ramp is complete or the cull distance, 8 to 64 m), reaching 32 m further towards the sun for casters; its axes are fixed in world space and its centre is snapped to its texels, so it does not crawl as the camera moves. Built once per frame, before the scene, from the batch that draws the world, with the flashlight map's casters (map cells, objects, characters through `draw_scene_casters`, the opaque PS1 prims through the caster shader) and the roofs of lights.json `ceilings` (the part within 96 m of the eye) in the depth layer only: alpha holes of fences, grates and leaves are never written, so light passes them; translucent texels do not tint the sun. Sampling: 12 compares on a rotated Vogel disc 1.5 texels wide, the receiver offset along its normal by a texel times (1 + slope), 2 view units of depth bias.
- **God rays** (`god_rays` with `volumetric_fog`, `inject.comp`): each froxel adds the sun where its shadow map sees it, at four points jittered along the froxel's depth (a thin trunk or post between two slices still breaks a shaft), times the Henyey-Greenstein phase with `fog_anisotropy`, `fog_scatter`, a sun share of 0.6 and soft_fog's transmittance to the froxel, so shafts are strongest near Harry and melt into the fog colour further out. The integration and composite are 7.12's: the fog's density stays the original ramp and the shafts only add light. The map lights still scatter unshadowed (now also with `map_lights`, not only with `rt_lights`). The map is built for the god rays even when `sun_shadows` is off.
- **Flake shadows** (`particle_shadows`): the weather (`engine/effects/weather.cpp`) notes every snow or ash flake it draws (`WeatherHost::note_flake`: the view position of the projected point and half its drawn size at its depth) into `scene::Frame::flakes`; the 64 nearest the flashlight's lens (else a point 3 m ahead of the camera) go to the scene shader, which treats each as a soft disc of opacity 0.55 (`FlakeShadow`): the light's cone at the flake (lens radius 9 units over the distance, or the sun's angular radius) sets how wide and faint its shadow is, sharp close to the receiver. It shades the flashlight in both paths (multiplying the shadow map's or the ray-traced result) and the raster sun. No shadow map, no acceleration structure: the flakes are not in the TLAS and do not shade the ray-traced sun.
- **Off**: with all four settings off the block is zero, no map is built and the image is the one without them.
- **Limitations**: map lights cast no shadows without ray tracing; the sun has one shadow map (no cascades) and no translucent shadows; the map lights' visibility in the fog is not modelled.

### 7.15 Muzzle flash light

A gun's shot lights its surroundings for as long as the original draws its muzzle flash (two to three updates: the flash's `life` in `gamedata/effects/combat_effects.json`). The light is data of the weapon: `muzzle_light` in `gamedata/weapons/<Name>.json` (colour, intensity, range, radius, `fade`, `casts_shadows`, `gi`); the handgun, the shotgun and the hunting rifle have a warm one, a weapon without the key lights nothing (melee weapons, the Hyper Blaster's beam, the motor weapons' smoke, the story shooters' guns, which have no weapon file).

- **Path**: the shot (`Combat_WeaponEffectSpawn`) notes which weapon made each flash kind (`slot_hosts::s_flashLights`); every frame the flash is drawn, `CombatEffects::draw_flash` reports its slot, kind, world muzzle point and age through `CombatEffectHost::flash_shown`, and the host hands an `effects::EffectLight` to `effect_light_shown` (keyed by the slot, so a frame drawn twice gives one light). `describe_map_lights` adds it to `scene::Frame::lights` like a map light and clears it with the effects shown, so it is gone the frame the flash is gone. The intensity falls linearly by `fade` over the flash's life. Shadow rays stop 0.1 m short of it so the barrel and the hand do not hide it.
- **Story shooters**: Cybil's and Kaufmann's guns have no weapon file; their entries of `combat_effects.json` "guns" (`CybilGun`, `KaufmannGun`) carry the same `muzzle_light` block, which `Combat_WeaponEffectSpawn` takes when no weapon file names the gun (a weapon file's own light wins).
- **Settings**: it is a frame light like those of lights.json, so it follows the same settings (and with `extra_lights` it also shades on GL and SDL3 GPU, 7.16): with `rt_lights` (ray tracing) it casts ray-traced shadows and bounces (`gi`); with `map_lights` (7.14) it shades the scene unshadowed, with the same fog rule (`1 − fog(distance)` from the light), and the volumetric fog scatters it; with both off, on GL and SDL3 GPU, the image is the original's (its own flash brightening, `map_lighting().flash()`, is unchanged in every case). It is the nearest light to Harry, so the 32-light limit never drops it.
- **Rendering only**: nothing is read back by the simulation; replays and handler traces do not change.

### 7.16 Extra lights (`extra_lights`)

Lamps placed by hand where a room draws its fixtures lit but the original gives them no light of their own: a light of `gamedata/maps/<map>/lights.json` with `"extra": true`. The data says which rooms and why (each file's and light's `description`); the condition that switches a lamp with the story is the light's `when` (event flags, [modding/data.md](modding/data.md#maps)), evaluated every frame by `describe_map_lights` like the other lights' flag conditions. Rendering only: the simulation never reads them, so replays and handler traces do not change.

- **Setting**: `extra_lights` (`GraphicsSettings::extra_lights`, Options > Graphics > Lighting, a preset key: on in the four ultra presets). Off: the host leaves the extra lights out of `scene::Frame::lights`; on: they join the frame with `FrameLight::extra` set.
- **Every renderer**: the scene shader's `MapLights` term (7.14) runs on GL, SDL3 GPU and native Vulkan alike. Where `map_lights` is off or cannot run (GL, SDL3 GPU), `describe_scene_lights` hands the shader only the extra lights (the 32 nearest that can reach the fog's visible range), without the sun; with `map_lights` they come with the map's other lights. Unshadowed, Lambert on the face normal, the fog of the way from the light, only ever added after the flashlight, so the original tint stays the floor and the darkness stays dark outside their short range. With ray tracing and `rt_lights` the traced path takes them like every map light: ray-traced soft shadows, bounce (`gi`), and their light in the volumetric fog.
- **Placed** (each file's `description` says why): the antique shop (map4_s01, cell ER0401): the table lamps on the red table and the standard lamp by the east wall, whose shades are the room's brightest texels; its ceiling has a plaster rosette but no fixture, so no ceiling light. The top of the lighthouse (map6_s02, RSU01FF): four low bulbs on the glowing seal of the floor, which the original draws glowing at every moment. The room of Harry's dream with Lisa (map4_s04, HU0103): a lamp where the original hangs its own light for the 'Where am I?' scene (57.0, -3.0, 141.8), on until the talk with Lisa ends (`!flag:M4S04_LisaTalkCutsceneDone`). Not placed: the hospital's in-house generator (map3_s01, `M3S01_GeneratorOn`) powers the elevator only and the basement cells (HPFFFF .. HP03FF) draw no lamp fixture; the Nowhere ward of Lisa's scene (map7_s01/s02, cell ER04FD) has no fixture and the original lights that scene with the flashlight only; the Otherworld examination room of map3_s04 keeps its flashlight-lit darkness.
- **Effect lights**: the muzzle flash (7.15) and the fires join this path (`FrameLight::extra`), so with `extra_lights` they also shade on GL and SDL3 GPU.
- **Fires** (`gamedata/effects/fire_lights.json`, `FireLight`): every flame particle a fire effect draws reports its world point and its share of light (`SlotEffectHost::flame_shown` from the particle emitter's flames, its drawn brightness; `FirePoolHost::flame_shown` from every fire pool particle, brightness times size). `describe_map_lights` puts one light per fire at the particles' weighted middle with an intensity that follows their sum (`full`, up to twice), times a render-side flicker noise (a hash of the frame count, never the game's random numbers); a fire that drew nothing keeps its light 4 presented frames, as the effects draw on update frames, then it is gone. So the burning lamp of the Split Head room flickers and dies out with its flames, and the Incubus's fire follows its fire balls. Observation only: the hooks run after the original's state changes and draw no random number.
- **Limitations**: these lights cast no shadows without ray tracing.

## 8. Debugging and checks

- Screenshots: the console command `SHOT <png>` reads the scene target (single-sample resolve with MSAA, 7.8) or the Vulkan device frame; test runs use a real GPU through SDL offscreen ([TESTING.md](TESTING.md)). Deterministic frames: `sh_replay.py run --shot`; comparison: `magick compare -metric AE` (RGB only, fuzz 3 %/10 %). Frame differences between builds come from snow and rain (random positions without input) and one-pixel geometry edges.
- `SH_GPU_STATS=1` — every 2 s a line `[GPU] splits … draws … scenes … failures …`.
- `SH_FMV_SHOT_FRAME=<n>` — screenshot of the n-th movie frame.
- Console: `FOGSOFT`, `SMOOTHMODELS`, `PGXP`, `WELD`/`WELDW` (seam welding of precise vertices), `CULL`, `flmode`, `shadow*`, `fogdist`, `WEATHERHZ`.
- Log: `[CULLSTAT]`, `[PKTARENA]`; per-category levels: `log_level` in `config.cfg`.

Known visible differences of the scene from the original: in `enhanced` the scene filters textures bilinearly, `original` uses nearest sampling; open model edges against fog are one pixel thicker (seams, 6.5).

## 9. Limitations

- Character skeleton and parts: logic builds the skeleton, link order and face translucency bit from ILM; the glb renderer reads the blend mode and translucency from those records; glb nodes are matched to parts by `extras.part_index`.
- A whole material with STP (a map script made the whole model translucent) and the texel `0x0000`: the original with the STP bit draws it black and blends it, the scene leaves it a hole; visible only in `average` mode.
- `HB_M*` clips in `HERO.glb` (extension `SH_anim_files` with one animation per file) are whole files, not split into the map's clip rows; `HB_WEP*` are not packed into the glb.
- Lamp glows (`Gfx_BillboardDraw`) are affine sprites on the original's whole screen grid: they do not read the camera twin (7.5) and may sit up to ~1 original pixel from the lamp.
- MSAA on SDL3 GPU: the backend reports `Caps::maxSamples = 1` and draws without MSAA, because SDL3 GPU pipelines are baked for the target's sample count and the pipeline caches do not key on it.
- Mods cannot add shaders; what mods can replace: [modding/assets.md](modding/assets.md).

## 10. Lights and materials

The data behind the map lights (`rt_lights` with ray tracing, 2.2b; `map_lights` without, 7.14; `extra_lights`, 7.16) and the materials. The original image is the reference: every term defaults to "as the original" (no new light where the original has none, fog ramp and darkness unchanged, the flashlight as calibrated), and modern lighting only refines how the existing sources light the world or adds sources the original image implies, by data.

- **Map lights**: `gamedata/maps/<map>/lights.json` — point and spot lights (metres, linear colour, intensity, range, emitter radius, `casts_shadows`, bounce, conditions by event flag names of `gamedata/flags/`), lights that follow a bone of Harry while an effect shows (the match of the opening alley), a sun and a sky for the daytime maps (none at night or in the Otherworld), roofs the cells do not draw (`ceilings`), and `extra` lamps (7.16). `gamedata/effects/lamp_lights.json` turns every lamp glow the original draws into a light while no sun shines. Muzzle flashes come from the weapon's `muzzle_light` (7.15), fires from `gamedata/effects/fire_lights.json`.
- **Materials**: one file per material, `gamedata/materials/<Name>.json` (roughness, metalness, `reflective`, `wet`), matched by texture page stem, pictureless material name or rectangles of a page (texture pages are atlases); details in 2.2b. Under them lie the import's inferred proposals (`convert/surface_materials.json`, made at import, never at run time, so results are stable): per page, from the picture's statistics; conservative, since pages are atlases. A file in `gamedata/materials/` patches an inferred entry key by key; a mod patches both.
- **Shading**: GGX specular (Smith-Schlick visibility, Schlick Fresnel) on materials that reflect, Lambert diffuse; the original per-vertex tint stays the ambient floor and the flashlight's own diffuse term stays the calibrated one. The raster path is Lambert only.
- **Fog bounds everything**: a light is dimmed by the fog of its way, the sun fades with the fog between the eye and the point; the volumetric fog scatters the nearest lights.
- No numeric ids: a material is its name, a light is its name.

## 11. Ray tracing

Native Vulkan only, standard KHR extensions (`VK_KHR_acceleration_structure`, `VK_KHR_ray_query`), no vendor library; hybrid (rasterised primary visibility, ray queries in compute for secondary effects). The implementation is in 2.2b; the settings in 7.1.

- **Flashlight shadows** (`rt_shadows`): rays to the lens disc, soft like the PCSS (7.9), which stays the fallback; alpha holes pass light, translucent texels tint it.
- **Reflections** (`rt_reflections`): on materials marked `reflective` and the water, at most as rough as 0.6; additive and subtractive materials never reflect.
- **Bounce light** (`rt_gi`): one bounce of the flashlight and the map lights, at most 16 m.
- **Fog and darkness**: no ray goes past the fog's opaque distance; what a ray finds is fogged along its own stretch and a miss returns the fog colour (black indoors and in the Otherworld). Ray-traced light is only ever added: a pixel in full darkness is identical with and without ray tracing.
- **Denoiser**: own temporal and a-trous filter (2.2b).
- **Limitations**: the map lights take one shadow ray for the strongest light and one for a light picked by its share (no ReSTIR, no radiance cache); reflections are always rays (no screen-space pass).

## 12. Texture upscaling at import

**Experimental**, off by default (`texture_upscale` 0/2/4; Options > Graphics; the `_upscaled` presets take x2). Textures are upscaled by Real-ESRGAN (`realesrgan-x4plus`) on ncnn's Vulkan compute, in the background, never per frame; the original textures return with the option off. The output is derived from the disc and lives only in the player's `gamedata/cache`.

- **Tool**: `tools/sh-upscale`, its own executable beside the game (the game does not link ncnn). Built when CMake finds ncnn in `SH_UPSCALE_NCNN_PREFIX` (`tools/ncnn/build.sh` builds ncnn and fetches the model, pinned by tag, commit and SHA-256; the dependency scripts of [BUILDING.md](BUILDING.md) call it); the model is copied beside the tool (`upscale-models/`). On Windows `sh-upscale.exe` opens the Vulkan loader at run time.
- **Input**: the PNGs the import writes (`convert/textures/**/*.png`, palette variants as their own files); fonts, `.subtract`/`.add` layers and `TEST/` are skipped. Tiles are sized by the device's memory budget (`--tile`), the colour of transparent texels is bled from their solid neighbours first; the alpha is scaled nearest, so the three alpha classes and the cut-out edges stay exactly the original's. x2 is the x4 result averaged down; no side above 2048. x4 tends to look smeared, which is why the presets take x2.
- **Lettering**: the network repaints small letters, so the textures with lettering are listed in `gamedata/config/texture_upscale.json` (texture name, optional `rects` in texels, `description`; mods extend it with a patch, records by `name`) and scaled with a Lanczos-3 filter instead, whole or only in the rectangles. The tool remembers the lettering each picture was made with, so a changed entry remakes just that picture.
- **Cache**: `<gamedata>/cache/upscale/realesrgan-x4plus-x<scale>-v<version>/<Folder>/<NAME>[.<label>].<source hash>.png`, with `progress` and `complete`; the readers use a picture only when the hash of the bytes they read matches, so a mod's picture or a re-import never shows a stale result.
- **Mods win**: a picture a mod replaces is drawn as the mod made it; the game passes the replaced keys to the tool (`--skip`) (`tests/assets/texture_upscale_test.cpp`).
- **Running**: the game starts the tool at start, from the Options row and when the lettering list or the mods' pictures changed; one run at a time, lower priority, log in `upscale.log`. Every picture is drawn as soon as its file is written: the game lists the pictures it waits for in `cache/upscale/wanted` (most recently loaded first), and the readers (`scene::refresh_textures`, `gltf_chara::refresh_textures`, the 2D pictures) take the better file (`engine/assets/texture_upscale.h`, `improved()`). Map textures get a mip chain (3.5); 2D pictures read into video memory are drawn as replacement pictures over their place (`engine/app/loader/upscaled_pictures.h`).
- **Limitations**: fonts stay the original; 2D pictures whose palette mixes semi-transparent and solid colours stay in video memory, and 2D pictures use palette row 0 only; item models drawn from the indexed sheets (inventory and pickup previews) are not upscaled; characters and items get no mip chain; the network smooths the dithering of soft gradients.

## 13. Tessellation and mesh shaders

One setting, **Model upscaling: Off / Tessellation / Mesh shaders** (`model_upscaling`, experimental, off by default; the `_upscaled` presets take Tessellation). Both paths give the same shape (PN triangles, 7.11); the choice is about speed on the player's GPU. Tessellation uses the core `tessellationShader` feature; mesh shaders need `VK_EXT_mesh_shader` and are skipped by the Options row (with the reason in its help) where it is missing, falling back to tessellation. The game has no height maps, so there is no displacement: tessellation only rounds silhouettes. UVs, skinning, vertex colours, transparency classes and collision are untouched; the ray-tracing structures keep the plain triangles; a mesh a mod supplies is never upscaled. GPU time of both paths is in the profiler overlay (`upscale tess`, `upscale mesh`, `upscale map`).

- **Limitations**: the inventory and pickup previews are not upscaled.
